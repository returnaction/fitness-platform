# Вопросы и решения

## Q004 — прямое хранение ключа идемпотентности

- Решение пользователя от 2026-11-17: хранить UUID напрямую вместо SHA-256 digest.
- Причина: ключ является идентификатором запроса, а не паролем; прямой UUID
  упрощает чтение кода и сопоставление запроса с результатом в БД.
- Внешний Idempotency-Key сохранён. Последующим решением пользователя
  преобразование в UUID перенесено в Spring MVC через UUID-параметр контроллера;
  отдельная проверка канонической записи и парсер удалены.
  Поиск включает user_id, авторизация и повторная проверка под блокировкой сохраняются.
- SQL, Entity, репозиторий, сервисы и тесты согласуются с idempotency_key UUID.
- Хеши прежних ключей необратимы. Перенос ранее применённой схемы и её данных
  не выполняется этой правкой; старые результаты нельзя просто удалять.

## Q003 — отдельные status и claim

- Решение пользователя от 2026-11-17: сохранить `GET /api/v1/coins/daily-reward/status`
  и `POST /api/v1/coins/daily-reward/claims`.
- Причина: открытие экрана читает состояние без начисления, нажатие получает
  подарок и возвращает сумму, оба баланса и время следующего получения одним ответом.
- Для таймера используются nextClaimAt и serverTime. Повтор claim по ключу
  возвращает исторический снимок; при необходимости свежие данные читаются через status.
- Затрагивает R06–R07 и проверку контрактов. Статус: решение принято;
  правильность реализации и тесты этим решением не подтверждены.

## Q001 — календарный день награды

Уточнение пользователя: подарок доступен раз в сутки, повторно через 24 часа.
Окончательное решение пользователя: только скользящие 24 часа от последнего
получения, без отдельного календарного условия. Пример: сегодня в 17:00 UTC →
следующее получение завтра не раньше 17:00 UTC. Решение зафиксировано в spec.md;
claim_date удалён из SQL. См. [изменения SQL](sql-review.md).

- Затрагивает T002–T006, временные границы API и UI.
- Дополнительный вариант: только скользящие 24 часа без календарного условия.
- Свидетельство: ранее прочитанный Python `daily_reward.py` использует timezone
  профиля и 24 часа; документация Java `33-coins-wallet-and-reward.md` описывает UTC
  и 24 часа и явно отмечает отличие от Python.
- Варианты: сохранить UTC либо явно согласовать перенос правила timezone профиля.
- Прежняя рекомендация сохранить календарное UTC отменена решением пользователя.
- Статус: решён; правило реализовано в DailyRewardAvailability и сервисах.
  Целевые тесты и сквозная backend-проверка прошли; работа принята пользователем.

## Q002 — размещение подарка

  главного экрана рядом с доступным и заблокированным балансом.
- Решение пользователя от 2026-11-17: подарок справа от балансов в шапке Home,
  карточку Daily bonus с Account удалить. По уточнению пользователя выход

- Сравнение: main 150948b уже содержит оба баланса в Home AppBar, без подарка.
- Статус: размещение согласовано. Пользователь разрешил реализацию и проверки.
  Сообщение об успехе — 5 секунд, галочка остаётся; по нажатию на неё
  показывается время до следующего подарка также на 5 секунд.
