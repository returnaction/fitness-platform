# Проверка Spec 011

Дата: 11 ноября 2026. Ветка: `37-mobile-flutter-auth`. Изменения сохраняются
локальными commit; push, merge и миграции пользовательских баз не выполняются.

## Что изменено

- Контракты создания профиля и кошелька переименованы в рамках v1 вместе с
  серверами Accounts/Coins и клиентами Identity. Старые имена не поддерживаются.
  Поля protobuf, mTLS и permission `identity.registration.provision` сохранены.
- Дополнительные переименования регистрации, сессий, безопасности Gateway и
  идентификаторов запросов выполнены по таблице плана. REST-пути, JSON-поля,
  SQL, порядок блокировок и транзакционные границы при этих переименованиях
  не менялись.
- Coins разделён на `wallet/service`, `repository`, `entity`, `grpc`.
  Создание выполняется JPA repository через атомарный `INSERT ... ON CONFLICT
  DO NOTHING` в короткой транзакции сервиса. Liquibase-схема не изменена.
- Все пять полей сущности сверены с [миграцией Coins](../../services/coins-service/src/main/resources/db/changelog/changes/001-create-coin-wallets.sql).
  Тесты читают сущность через JPA, проверяют каждый баланс и обе временные метки.
- gRPC Coins обязателен при запуске; отсутствие или повреждение сертификата
  останавливает запуск. Адаптер отделяет UUID-валидацию, операцию и отправку
  ответа после commit. Ошибки БД остаются безопасным `INTERNAL`.
- Добавлен production-профиль; удалены неиспользуемые зависимости validation и
  MVC test. Не добавлялись финансовые операции, mapper или лишние интерфейсы.
- Документ подготовки PostgreSQL переименован в `database-setup.md`; ссылки и
  актуальные описания обновлены. Старые имена сохранены только в явно
  исторических журналах Spec 001/002/009/010 и таблице миграции Spec 011.

## Сборка и окружение

Использованы JDK Temurin 25.0.5, Maven Wrapper 3.9.11 и настройки проверок из POM.
В этом Windows-окружении `mvnw.cmd` завершается ошибкой определения кеша Maven;
Wrapper запускается через Git Bash с
`JAVA_TOOL_OPTIONS=-Duser.home=C:\Users\Oberg`.

Первый `clean verify` в рабочей папке остановился: работающий процесс удерживает
JAR Gateway. Для проверки скопированы отслеживаемые и новые неигнорируемые
исходники во временный каталог, без `.git`, `target`, `.env` и секретов.
Git worktree не создавался, рабочие процессы не останавливались.
После исправлений 303 файла кода, контрактов, конфигурации, скриптов, POM и
Wrapper сверены по SHA-256: рабочая папка и проверенная копия совпадают.

В чистой копии `clean verify` выполнил тесты контрактов, Gateway и Identity,
затем обнаружил семь ранее кешированных нарушений форматирования Identity.
`spotless:apply` исправил их; подтверждено, что изменения затрагивают только
пробельные символы, и исправления перенесены в рабочую папку.
После этой коррекции `verify` успешно проверил контракты, Gateway, Identity и
Accounts. В Coins он обнаружил ненужное подавление SpotBugs в gRPC-адаптере;
аннотация удалена. Повторный `verify` для Coins и пяти остальных сервисов
с `-am` завершился `BUILD SUCCESS`. Таким образом, все модули прошли тесты,
Spotless и SpotBugs; это последовательные проверки с продолжением после
исправлений, а не заявление об успешном первом запуске `clean verify`.

Команды после первоначального `clean verify`:

```text
./mvnw spotless:apply
./mvnw verify
./mvnw -pl services/coins-service,services/challenge-service,services/video-proof-service,services/moderation-service,services/exercise-catalog-service,services/notifications-service -am verify
```

## Ограничения

Ручные smoke-тесты локальной step-ca включаются отдельным системным свойством;
они не входят в обычный Maven-запуск. Автоматические mTLS-тесты используют
краткоживущие тестовые сертификаты. Результаты пропущенных проверок не заявляются.
Рабочие пользовательские процессы со старыми JAR не перезапускались.
