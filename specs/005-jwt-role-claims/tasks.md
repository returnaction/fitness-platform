# Задачи: роли пользователя в access JWT

> **Спецификация:** [spec.md](spec.md)
> **План:** [plan.md](plan.md)
> **Статус:** approved

Отмечать задачи только после реализации и проверки; номера последующих веток
определяются по правилам репозитория в момент начала работы.

## Подготовка

- [x] Согласовать задержку изменения ролей в старом access и область первой
  проверки: до 15 минут и тестовый endpoint без production API Accounts/Coins.
- [x] Согласовать массив назначенных ролей, поведение старых токенов без ролей
  и иерархию `SUPER_ADMIN → ADMIN → MODERATOR → USER`.
- [x] Согласовать `401` для некорректного типа claim, `500` для отсутствия
  назначенных ролей у активного пользователя и `503` при недоступности БД.
- [x] Согласовать порядок изменения ролей и выдачи токена и сохранение актуальной
  проверки `SUPER_ADMIN` для административного восстановления.
- [ ] Сверить JPA-модель, схему, транзакции и пути создания токена.
- [ ] Зафиксировать JWT-контракт, ошибки и безопасную совместимость.

## Реализация

- [ ] Добавить чтение назначенных ролей Identity через JPA-репозиторий.
- [ ] Добавить проверенный claim в выдачу access при регистрации, входе и refresh.
- [ ] Реализовать согласованную проверку JWT и ролей на стороне потребителя,
  не создавая production endpoint без согласования.
- [ ] Обновить документацию и примеры без настоящих токенов.

## Проверка и выпуск

- [ ] Проверить одну и несколько ролей, PENDING, отсутствие / ошибки ролей.
- [ ] Проверить изменение роли и актуальность нового JWT после refresh.
- [ ] Проверить некорректный JWT, подпись, issuer, audience, срок, `401` / `403`.
- [ ] Проверить наследование прав между ролями на тестовых endpoint;
  бизнес-правила доступа к чужим ресурсам определяются отдельными задачами.
- [ ] Проверить конкурентное изменение роли и выдачу JWT на временной PostgreSQL.
- [ ] Запустить сборку, релевантные тесты и сквозной сценарий; зафиксировать ограничения.
- [ ] Сверить критерии и статус, после создания PR записать фактический результат.
