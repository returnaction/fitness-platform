# Проверка Spec 008

## Итог на 2026-11-11

Spec 008 реализована и проверена в согласованном локальном Android-окружении.
G1–G6 закрыты. Подтверждены пять auth-операций через Gateway на телефоне и
эмуляторе; отказ отозванного access и локальный выход при недоступности Identity
на эмуляторе; сохранение сессии при искусственном 503 и отсутствие повторного
refresh после потери успешного ответа на телефоне. 48 автоматических тестов,
analyze, format и APK-сборки прошли на текущем коде приложения.

Ограничения: ошибки secure storage проверены подменой хранилища в тестах,
а не физическим повреждением Android Keystore. Отказ refresh моделировался
loopback proxy; это не реальный отказ БД Identity. Точный HTTP-статус ответа
на outage-запрос эмулятора не перехватывался. Первый register 504 из раннего
этапа остался без установленной первопричины; успешный повтор подтверждён.
Содержимое профиля/кошелька отдельно не проверялось: это не критерий клиентской
Spec 008, которая использует auth-контракт. Проверка release, production HTTPS
и iOS не заявляется. Push, PR и merge не выполнялись.

Ниже сохранена история этапов: прежние записи об открытых задачах описывают
состояние на момент этапа, а не итоговый статус.

## Физический Android по USB — 2026-11-11

Проверена debug-версия Fitness App на Samsung SM-S938B. Клиент использует
`API_BASE_URL=http://127.0.0.1:8088`, настроен `adb reverse tcp:8088 tcp:8088`.
Backend запущен из основного checkout; копирование локальных конфигураций
в worktree само по себе не означает проверку запуска backend из worktree.

Результаты подтверждены UI-иерархией телефона и счётчиками
`http_server_requests_seconds_count` на management-порту Gateway 8089:

| Сценарий | Наблюдение |
| --- | --- |
| Регистрация | Первый запрос получил Gateway 504. Повтор неизменной открытой формы завершился 201, появился `You are signed in`. |
| Перезапуск | После force-stop и запуска приложения показан `You are signed in`; Gateway зарегистрировал refresh 200. |
| Logout | Gateway зарегистрировал 204, телефон вернулся на Welcome. |
| Login | Вход тестового пользователя с телефона завершился успешно, показан `You are signed in`. |
| Logout-all | Отображён диалог подтверждения; после подтверждения Gateway зарегистрировал 204, телефон вернулся на Welcome. |
| Отзыв второй сессии | Перед подтверждением logout-all создана дополнительная тестовая сессия через Gateway. После выхода с телефона её access-token получил 401 `invalid_access_token` на logout-all. Метрики CheckSession: один `active`, один `invalid`. |

На момент снятия метрик: register 504 ×1 и 201 ×1, login 200 ×3
(один с телефона и два контрольных запроса), refresh 200 ×1, logout 204 ×1,
logout-all 204 ×1, отклонённый запрос 401 ×1.
Тестовый пользователь создан в разрешённой локальной тестовой БД;
его учётные данные и токены в документ не включены.

## Дополнение G3/G4 — 2026-11-11

Устранён риск повторной отправки одноразового refresh после завершения процесса:
пара удаляется до сетевого запроса; если удаление не удалось, запрос не отправляется.
После подтверждённого 503 identity_unavailable прежняя пара записывается обратно.
При завершении процесса до обработки ответа приложение потребует нового входа.

Ошибка storage теперь предлагает локальную очистку без refresh. Ошибка входа
не превращает Welcome в экран ошибки восстановления. Поля формы блокируются
на время отправки, ошибка сохранения токенов отображается безопасно. Сообщение
о неподтверждённом удалённом выходе использует живущий выше экрана ScaffoldMessenger.

Проверки: `dart format lib test`, `dart analyze` (No issues found),
`flutter test` — 23 теста прошли. Добавлены сценарии refresh 401/403/502/504,
ошибки удаления/записи, запись пары после ротации и widget-тесты входа,
Show password, ключа регистрации и очистки storage.
Эти тесты не заменяют оставшиеся проверки G4/G5.

`flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8088`
завершилась с кодом 0; debug APK создан. Эту новую сборку пока не проверяли
на устройстве. Служебный каталог `android/.kotlin/` исключён из Git.

Дополнительно выполнены HTTP-тесты с реальным Dio и подменённым транспортом:
все пять маршрутов, единый URL Gateway, методы/тела/заголовки, отсутствие
повторов при 413/429/502/503/504, Retry-After и некорректные типы полей ошибки.
Полный набор: 34 теста прошли. Реальные внешние запросы эти тесты не выполняют.

ошибка приложения этим результатом не доказана. Во время запуска на хосте
оставалось менее 100 MiB свободной физической памяти.

Эмулятор остановлен командой `adb emu kill`, без wipe-data. Данные AVD,
телефон и backend не очищались. G5 Android Emulator не выполнена: нужен
работоспособный Android с разблокированным пользователем и достаточный
запас памяти хоста. Проверки 503 и потери уже обработанного ответа в этой

## Искусственные отказы на физическом телефоне — 2026-11-11

Добавлен `scripts/mobile-fault-proxy.py`: слушает только 127.0.0.1:18088,
разрешает пять auth POST-путей, перенаправляет их только в настоящий Gateway
127.0.0.1:8088. Первый refresh получает выбранный отказ; последующие запросы
проходят обычно. Тела, токены и заголовки не выводятся и не записываются.
Телефон временно подключён через `adb reverse tcp:8088 tcp:18088`.

1. В режиме `503` login через Gateway вернул 200. После перезапуска приложения
   proxy ответил 503 identity_unavailable без передачи refresh серверу.
   На Samsung показаны `Service is temporarily unavailable.`,
   `Your session is kept on this device.`, `Try again` и локальный выход.
   Нажатие Try again отправило один refresh через Gateway (200), затем
   приложение показало `You are signed in`.
2. Proxy перезапущен в режиме `drop`. При восстановлении он передал refresh
   Gateway, получил 200, прочитал ответ и закрыл соединение без передачи ответа
   телефону. Приложение показало Welcome. Ещё один полный перезапуск оставил
   Welcome; в выводе proxy был только один refresh, повторного запроса не было.

Это проверка поведения реального APK и platform secure storage на устройстве
при искусственном сетевом отказе. 503 создан тестовым proxy, а не реальным
отказом БД Identity; в drop-сценарии успешная обработка refresh реальным
Gateway подтверждена. Содержимое токенов не извлекалось из телефона.
Оба proxy-процесса завершены, прямой маршрут tcp:8088 → tcp:8088 восстановлен
и проверен через `adb reverse --list`. Backend не останавливался.

Остаётся G5 Android Emulator. Ошибки чтения/записи/удаления secure storage
проверены автоматически через подмену хранилища, а не физическим отказом
Android Keystore. Spec 008 целиком пока не завершена.

## Завершение G5: отзыв и реальная недоступность Identity — 2026-11-11

В повторяемом сценарии email в форме эмулятора сравнен с контрольным значением
без вывода содержимого. После успешного UI login отдельная контрольная сессия
выполнила logout-all через Gateway: 204, повтор тем же access: 401.
Затем logout-all из эмулятора увеличил CheckSession invalid ещё на один,
не увеличив число успешных logout-all. Приложение перешло на Welcome.
Итоговые счётчики того сценария: active 5, invalid 3, logout-all 204 — 5.
Первый пробный прогон дал неожиданный 204 и не засчитан как проверка отзыва;
причина расхождения не установлена. Зачтён только повтор с проверкой email
и контрольного токена после отзыва.

Для outage создана новая сессия в эмуляторе. Подтверждённый процесс локального
Identity остановлен; пользовательский logout-all завершился локальным Welcome.
Успешный logout-all и CheckSession active не увеличились. Точный статус ответа
эмулятору не захватывался; 503 не заявляется как непосредственно измеренный
результат этого сценария. Это реальная проверка поведения при остановленном
Identity; отдельная проверка 503 refresh ранее выполнена на телефоне через proxy.

Identity восстановлен с прежним JAR, local-профилем и рабочим каталогом основного
checkout. Подтверждены запуск на 127.0.0.1:8080, контрольный login через Gateway
200 и очищающий logout-all 204. После восстановления backend полный перезапуск
приложения оставил Welcome. Эмулятор и backend оставлены работающими.

По совокупности сценариев и автоматических тестов критерии G5 выполнены.
G6 закрыта обновлением инструкции и результатов; статусы spec/plan/tasks
изменены на implemented. Код Flutter и Java в заключительных проверках не менялся.
