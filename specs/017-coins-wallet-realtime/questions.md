# Решения Spec 017

- Пользователь поставил задачу: как приложение изнутри понимает, что баланс
  обновился на UI в реальном времени. Запрошен пакет документов в формате
  Spec 016. Разрешены только документы; реализация не запускалась.
- Номер 016 занят контейнерной спекой, 015 — мобильным профилем в параллельной
  ветке 41. Для этой работы предложен 017; свободный номер и ветка требуют
  подтверждения пользователя (Q7).

- Сверка 2026-11-14 по докам 33/36/58 и коду: дока 33 уже делит задачу на два
  этапа. Этап 1 — GET /api/v1/coins/me при открытии экрана, после собственных
  операций и при возвращении в приложение; фоновое изменение на открытом экране
  автоматически не появляется. WS отложен и требует отдельного проекта
  версионирования, авторизации, восстановления пропущенных обновлений и надёжной
  публикации. GET-сверка обязательна и при WS — этап 1 является фундаментом.
- Coins: только gRPC CreateWalletIfAbsent; REST и операций изменения баланса нет;
  coin_wallets без version. Gateway: WebMVC servlet-прокси, дедлайн запроса,
  CheckSession на каждый запрос, каталог IDENTITY/ACCOUNTS; WebSocket
  WebMVC-вариант не проксирует. Notifications — скелет; док 58 проектирует
  Kafka → история → device push, а не WS-канал баланса. Kafka локально нет;
  Docker вне объёма Spec 013. Новые публичные маршруты Coins вне Spec 013 —
  требуется эта спека.
- Фоновые изменения баланса существуют (награды, резерв, распределение),
  поэтому ответа мутации недостаточно: push действительно нужен. Типы
  COINS_CREDITED/STAKE_RETURNED из дока 58 не покрывают reserve/release/
  settlement (locked balance).

- Открытые вопросы ниже требуют решения пользователя до начала этапа 2
  (T007–T010). Рекомендации — предложение, не решение.
- Не решено (Q1, транспорт): (а) отдельный WS-endpoint минуя Gateway —
  противоречит направлению «внешний вход только через Gateway», нужно явное
  решение; (б) доработка Gateway под WS — большой объём в самом сложном
  сервисе; (в) SSE с исключением дедлайна — ломает per-request CheckSession.
  Рекомендация: (а) с фиксацией решения.
- Не решено (Q2, издатель): notifications-service (смешение с доменом
  истории/push дока 58) vs coins-service. Рекомендация: notifications только
  при явном расширении его ответственности; иначе coins.
- Не решено (Q3, событие): нужен coins.balance_changed на каждую ledger-операцию,
  меняющую баланс, а не только два типа из дока 58. Подтвердить.
- Не решено (Q4, инфраструктура): локальный MVP без брокера (afterCommit вызов
  coins → издатель; потеря лечится GET) vs ждать Kafka. Outbox уже в доке 36.
  Рекомендация: MVP без брокера с явной записью ограничения.
- Не решено (Q5, version): BIGINT в coin_wallets, инкремент в той же транзакции;
  в событии и GET; клиент применяет только более новый. Миграция требует
  отдельного разрешения.
- Не решено (Q6, авторизация WS): JWT на handshake + gRPC CheckSession (паттерн
  Gateway), периодическая перепроверка, закрытие при отзыве сессии; локальное
  допущение Spec 013. Подтвердить.
- Не решено (Q8, порог и background): целевая задержка появления фонового
  изменения; закрывать ли WS в background. Рекомендация: закрывать, refetch
  при resume.

- Этап 1 (T003–T006) может быть разрешён отдельной командой, не дожидаясь
  решений этапа 2. После каждого разрешённого пункта — остановка для ревью,
  без коммита агента.
- Черновик остаётся открытым для дополнений пользователя; новые проблемы
  самостоятельно в объём не включать.
- Реализация не начиналась, проверки не выполнялись. Актуальные результаты
  и ограничения будут приведены в [verification.md](verification.md);
  дальнейшие задачи требуют отдельного выбора пользователя.
