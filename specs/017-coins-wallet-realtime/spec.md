# Spec 017: обновление баланса Coins на UI в реальном времени

> **Статус:** draft — реализация не разрешена
> **Ветка:** не выбрана; номер 017 требует подтверждения (questions.md, Q7)
> **Дата:** 2026-11-14
> **Документы:** [план](plan.md), [задачи](tasks.md), [вопросы](questions.md), [проверка](verification.md).

## Цель

Приложение показывает актуальный баланс без ручного обновления. По доке 33
(кошелёк и ежедневная награда) задача разделена на два этапа: этап 1 — GET
по триггерам (согласованное поведение первого этапа); этап 2 — WebSocket-push
для открытого приложения (проектируется отдельно). GET-сверка обязательна
и при WS: при первом открытии и восстановлении после обрыва.

## Подтверждённое состояние

Сверка по содержимому файлов и проектным документам на 2026-11-14;
запуск приложений и проверки не выполнялись:

| Компонент | Есть сейчас | Отсутствует для задачи |
| --- | --- | --- |
| [coins-service](../../services/coins-service/) | gRPC `CreateWalletIfAbsent`, `WalletEntity` (available/locked) | REST, операции изменения баланса, события, `version` |
| [gateway-service](../../services/gateway-service/) | WebMVC servlet-прокси, дедлайн запроса, CheckSession на каждый запрос; каталог IDENTITY/ACCOUNTS | Маршрут COINS; проксирование WebSocket (WebMVC-вариант не умеет) |
| [notifications-service](../../services/notifications-service/) | Скелет: security, фильтры | WS/push, потребители событий |
| [apps/mobile](../../apps/mobile/) | Flutter, Riverpod + Dio, фича profile | Фича wallet, WS-клиент |
| [contracts](../../contracts/) | Proto создания кошелька; OpenAPI identity/accounts/gateway | `coins-v1.yaml`, контракт события баланса |
| Инфраструктура | Локальные Java-процессы, PostgreSQL (Spec 013) | Kafka; Docker вне объёма |

Проектные ограничения: док 33 явно откладывает WebSocket и требует отдельного
проекта версионирования, авторизации, восстановления пропущенных обновлений
и надёжной публикации. `coin_wallets` не содержит `version` (док 36).
Док 58 проектирует Notifications как Kafka → история → device push, а не
WS-канал баланса; типы `COINS_CREDITED`/`STAKE_RETURNED` не покрывают
reserve/release/settlement. Новые публичные маршруты Coins вне Spec 013 —
требуется эта спека. Фоновые изменения баланса существуют (награды, расчёты),
поэтому push действительно нужен, а не только ответ мутации.

## Согласованный объём

Объём ниже — предложение черновика; считается согласованным только после T002.

1. Этап 1, Coins: `GET /api/v1/coins/me` → `{"availableBalance":10,"lockedBalance":20}`;
   владелец из проверенного контекста; ошибки по доке 33. Отсутствие кошелька
   активного пользователя — сигнал инварианта, не фиктивный ноль.
2. Этап 1, Gateway: upstream COINS и маршрут `GET /api/v1/coins/me, COINS,
   AUTHENTICATED` в каталоге; дедлайн и CheckSession сохраняются; `coins-v1.yaml`.
3. Этап 1, Flutter: фича wallet по образцу profile (repository/controller/screen);
   refetch при открытии экрана, после собственной операции с монетами и при
   возвращении в приложение. Ответ повтора операции — исторический снимок,
   для актуального баланса нужен GET.
4. Этап 2 (после решений questions.md): WS-push изменений баланса только
   авторизованным соединениям владельца; `version` против устаревших событий;
   GET-сверка при открытии и реконнекте; закрытие соединения при отзыве сессии.

Транспорт, издатель, источник событий, версионирование, авторизация и
инфраструктура этапа 2 не выбраны и фиксируются решением до кода (Q1–Q6).
Этап 1 не ослабляет Gateway и не протаскивает WS через servlet-пайплайн.

## Вне объёма

Серверное развёртывание, Docker и его сеть, Kafka-инфраструктура без отдельного
запроса (Spec 013). История операций, daily-reward claim, ставки и settlement —
отдельные спеки. Изменение домена уведомлений (док 58): WS-баланс не смешивается
с историей/push без явного решения. Административные операции. Миграции
пользовательских БД без отдельного разрешения. Коммит, push, merge и deploy
агентом не выполняются.

## Сценарии и критерии готовности

- [ ] Этап 1: GET через Gateway с действующей сессией — 200 с балансом владельца;
  без сессии — 401; чужой баланс недоступен.
- [ ] Этап 1: UI обновляется по трём триггерам; фоновое изменение на открытом
  экране до следующего обновления не появляется (согласованное поведение).
- [ ] Этап 1: отсутствие кошелька активного пользователя обработано как сигнал
  инварианта; ошибки не раскрывают чужой баланс и внутренние детали.
- [ ] Этап 2: фоновое изменение появляется на открытом экране без действий
  пользователя; устаревшее событие не применяется; повтор/дубль безопасен.
- [ ] Этап 2: разрыв соединения → reconnect и GET-сверка; отзыв сессии закрывает
  соединение; два устройства одного пользователя получают событие.
- [ ] Maven verify затронутых модулей, Spotless/SpotBugs, flutter analyze/test,
  Markdown-ссылки и git diff --check проходят; контракты и документы обновлены.
- [ ] Результаты и ограничения записаны; недостающая среда фиксируется как
  непроверенный критерий, а не как успех.
