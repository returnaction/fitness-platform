## Исходное состояние до T002

`apps/mobile/lib/app/fitness_app.dart` после авторизации показывает AccountScreen
с `You are signed in`. Нижней навигации и реализации профиля нет.
Есть AuthRepository, SessionOperationCoordinator и защищённое хранение токенов.
IdentityApiClient поддерживает POST; его модель ошибки не сохраняет details и
requestId. Эти сведения получены чтением кода, не запуском тестов.

## Подход

1. Проверить текущий код, инженерные стандарты, контракт и существующие тесты.
2. Добавить клиентские модели профиля и GET/PUT через Gateway с существующей
   авторизацией и координацией refresh/logout. Не ломать auth-клиент; сохранять
   структурированные ошибки без отображения технических деталей пользователю.
3. Выделить состояние профиля и локальный адаптер хранения. Рассмотреть уже
   подключённый flutter_secure_storage, проверить привязку к аккаунту и очистку.
   Персональные данные и черновики не логировать. Не добавлять зависимости без
   необходимости; при необходимости проверить совместимость и закрепить версию.
4. Защитить состояние от поздних ответов старой сессии и старых версий. Сохранять
   маркер незавершённого PUT до отправки, учитывать сбои локального хранилища.
   При невозможности надёжного восстановления не заявлять сохранение подтверждённым.
5. Добавить нижнюю панель, просмотр и отдельную форму, переиспользовать текущий
   выход. Для списка timezone изучить старый UI и выбрать совместимый источник
   IANA; серверный контракт не менять.
6. Обработать конфликты, потерянные ответы, уход из формы и завершение приложения.
   Сравнение значений для неизменённой формы и результата PUT учитывать серверную
   нормализацию; version использовать только для контроля конкурентности.
7. Выполнить автоматические проверки, затем реальные сценарии на телефоне.

## Границы и зависимости

Меняется только мобильный frontend, его тесты и документация. Данные принадлежат
Accounts; авторизация — Identity через Gateway. Серверные миграции не нужны.
Любую необходимость менять сервер или API сначала вынести пользователю на
обсуждение, зависимую задачу остановить до отдельного согласования.
Текущие локальные допущения серверной безопасности не объявлять устранёнными.

## Проверки

Использовать существующие средства Flutter: unit/widget-тесты состояния,
контракта клиента, формы, хранилища и гонок сессий. Запустить flutter analyze,
flutter test, flutter build apk --debug. Форматтер не запускать согласно AGENTS.md.
Серверный build для изменений только frontend автоматически не запускать.
Физический телефон и согласованный тестовый аккаунт обязательны для конечной
проверки; сценарии и запись доказательств — [verification.md](verification.md).

## Источник часовых поясов T005

Список выбора с поиском повторяет взаимодействие старого приложения. Вместо
новой зависимости используется снимок ZoneId.getAvailableZoneIds() из фактически
установленной Temurin 25.0.5+8-LTS, tzdb 2026e: 604 ID, как в валидаторе Accounts.
`apps/mobile/tool/ExportProfileTimezones.java` — инструмент генерации клиентского
списка, не код бэкенда. При смене JDK/tzdb Accounts снимок надо обновить и сверить.
Команда из корня репозитория в PowerShell:

```powershell
java apps/mobile/tool/ExportProfileTimezones.java | Set-Content -Encoding utf8 apps/mobile/lib/features/profile/profile_timezones.dart
```

Сервер остаётся источником окончательной проверки значений; изменения контракта
или серверных правил требуют отдельного обсуждения с пользователем.

## Исправление подтверждения записи Android — T008

ProfileStore использует DurableProfileStorage поверх прежнего шифрованного
flutter_secure_storage 11.0.0. После write/delete вызывается нативный flush через
MethodChannel fitness/profile_storage. На фоновой очереди Flutter Android выполняет
commit в тех же SharedPreferences (FlutterSecureStorage), сохраняя свежий случайный
служебный маркер без данных пользователя. Новый маркер заставляет повторить запись
снимка даже после неудачного предыдущего apply. Ошибка commit передаётся в
ProfileStorageException; PUT не отправляется до подтверждения pendingSave.
Профиль, accountId и pendingSave остаются одной зашифрованной записью.

Контракт Android commit/apply:
[SharedPreferences.Editor](https://developer.android.com/reference/android/content/SharedPreferences.Editor#commit()).
Имя preferences связано с закреплённой версией плагина и его стандартными настройками;
при обновлении плагина/namespace необходимо сверить адаптер и повторить device-тест.
Это гарантия ожидания записи перед запросом, не обещание защиты от отказа накопителя.
