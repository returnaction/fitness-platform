# Проверка мобильного профиля

> **Спецификация:** [spec.md](spec.md)  
> **Статус:** НЕ ВЫПОЛНЕНО. Это план проверки, не свидетельство работоспособности.

## Подготовка физического телефона

Пользователь подключает Android-телефон по USB, включает USB-отладку и разрешает
подключение компьютера. Исполнитель проверяет устройство через adb/Flutter,
фиксирует модель, Android, версию приложения и проверяемую ревизию, собирает и
устанавливает APK. Настроить доступ к существующему локальному Gateway по
инструкции apps/mobile/README.md; проверить серверную доступность.
Использовать согласованный тестовый аккаунт, не изменять реальные данные без
согласования. Не записывать пароль, токены и персональные значения в логи отчёта.

Если управление экраном инструментами недоступно, пользователь выполняет точные
шаги на телефоне, исполнитель сверяет наблюдаемый результат и безопасные логи.
Отмечать, какие действия и наблюдения выполнены пользователем. Не утверждать
визуальную или автоматическую проверку без фактического наблюдения.

## Обязательные сценарии

Все пункты пока НЕ ВЫПОЛНЕНЫ.

- [ ] Вход/регистрация: You are signed in, панель, недоступные Home/Challenges,
  доступный Profile; первый GET, все поля кроме version, Not set.
- [ ] Изменение каждого поля, Public/Private, выбор timezone, выбор/очистка даты,
  очистка необязательных полей; правильная клавиатура, прокрутка, отсутствие
  обрезанного текста и перекрытия Save клавиатурой на подключённом телефоне.
- [ ] Save с изменениями: один PUT, новая версия/данные; Save без изменений:
  отсутствие PUT. Уход без Save: предыдущие значения без подтверждения.
- [ ] Перезапуск: локальный профиль без GET; жест вниз: GET и обновление данных.
- [ ] Невалидные поля и занятый ник: понятные ошибки без потери формы.
- [ ] Конфликт версии: изменить тот же тестовый профиль другим клиентом через
  существующий API, получить 409 со старой формы, проверить Reload и его отказ.
- [ ] Потеря сети при первом GET и ручном обновлении: Retry, сохранение старых данных.
- [ ] Потеря ответа PUT: проверить перечитывание, отсутствие слепого повтора PUT,
  совпадающий результат и неопределённость при отличающихся данных/ошибке GET.
- [ ] Уход во время PUT: навигация доступна, повторное редактирование запрещено,
  успех обновляет копию без принудительного перехода, ошибка уведомляет.
- [ ] Завершение приложения во время PUT: при следующем открытии проверка GET,
  отсутствие автоматического повторного PUT.
- [ ] Истёкшая сессия: штатный refresh; окончательный отказ возвращает на вход
  и удаляет профиль/черновик.
- [ ] Выход на этом/всех устройствах, отмена и существующее подтверждение;
  выход во время PUT, игнорирование позднего ответа, очистка локальной копии.
- [ ] Вход другим тестовым пользователем не показывает данные предыдущего.

Для воспроизведения сетевых сбоев допускается тестовая подмена транспорта или
локальный тестовый proxy без изменений production-бэкенда. Отдельно указывать,
что проверено на реальном сервере, что с внедрённым сбоем и что только unit-тестом.
Не подменять обязательную проверку на устройстве результатом автоматических тестов.
Если сценарий пока невозможно воспроизвести, оставить его открытым и описать причину.
