## T003 — выполнено 2026-11-13

- ProfileStore сохраняет профиль и pendingSave одной записью в уже подключённом
  flutter_secure_storage. Запись привязана к sub текущей сессии; JWT разбирается
  только для локальной привязки, не для авторизации. Сервер по-прежнему проверяет Gateway.
- ProfileController восстанавливает локальную копию без GET, поддерживает явное
  обновление и сохраняет отображённые данные при ошибке. Первое открытие без копии
  и открытие с маркером незавершённого PUT вызывают GET.
- Маркер записывается до PUT; отказ записи предотвращает отправку. Успех сохраняет
  ответ и снимает маркер. Сетевые/неопределённые сбои оставляют его для восстановления;
  подтверждённые 400/409/415/422 снимают маркер. Черновик на диск не сохраняется.
- Смена сессии немедленно сбрасывает состояние, поздние ответы отбрасываются.
  Дисковые операции упорядочены: завершение старой записи не восстанавливает
  профиль после удаления. Старый GET не перезаписывает результат нового PUT.
- Очистка подключена к login/register, logout/logout-all, локальному выходу и
  окончательной потере сессии. Сбой удаления профиля сообщается через существующий
  результат очистки, доступен повтор; удаление профиля пытается выполниться даже
  при ошибке удаления токенов. Новых зависимостей и серверных изменений нет.
- `flutter test` — PASS: 79 тестов, 17 новых для T003. `flutter analyze` — PASS,
  замечаний нет. `git diff --check` — PASS.
- Ограничения: защищённый плагин подключён, но физическое хранение на телефоне ещё
  не проверено; тесты используют подменённое хранилище/транспорт, перезапуск

## T006 — выполнено 2026-11-13

- После timeout/сетевого сбоя, повреждённого успешного ответа или 5xx PUT выполняется
  проверочный GET. Совпадение нормализованных значений подтверждает текущее состояние,
  обновляет локальную копию и завершает форму. Несовпадение/ошибка GET оставляет
  pendingSave и черновик; повторный PUT запрещён до явного успешного Reload.
  Сам PUT автоматически повторяется только после явного 401 и штатного refresh,
  не после транспортной неопределённости.
- Конфликт версии сохраняет введённое, блокирует повторный Save и новое редактирование.
  Reload заменяет форму только после успешной загрузки; ошибка не уничтожает черновик.
  Сообщение и Reload расположены возле Save и видны без прокрутки длинной формы.
- Подключён результат отказа сессии к AuthController с проверкой поколения сессии.
  Окончательный отказ очищает профиль/черновик и возвращает на вход; сбой защищённого
  хранилища показывает существующее восстановление/локальную очистку. Временный
  identity_unavailable при refresh сохраняет сессию и форму.
- Закрываются маршруты авторизованного пользователя при завершении сессии;
  редактор скрывает данные при смене поколения. Поздние успехи/ошибки старой сессии
  не публикуют данные или уведомления новому аккаунту. Навигация/выход при PUT доступны.
- На клиенте добавлен sendTimeout 30s к существующим connectTimeout 15s и
  receiveTimeout 30s. Это транспортные лимиты, не обещание отмены серверного UPDATE.
- Добавлены 15 тестов: подтверждение потерянного ответа, несовпадение/ошибка проверки,
  conflict → failed/successful Reload, блокировка повторного сохранения, поздний PUT
  после выхода, GET/PUT с недействительной сессией, временный отказ refresh,
  сбой хранилища и выход → вход другим аккаунтом при старом незавершённом PUT.
  Тест перезапуска моделирует завершение контроллера во время PUT и пересоздание
  поверх той же локальной записи; реальное завершение Android-процесса остаётся T008.
- `flutter test` — PASS: все 116 тестов. `flutter analyze` — PASS, замечаний нет.
  `git diff --check` — PASS. Тесты UI используют настоящие AuthRepository/
  AuthController и Dio с подменённым транспортом и хранилищем там, где проверяется
  связка авторизации и профиля; это не реальные запросы к работающему Gateway.
- Бэкенд/контракт/миграции не менялись; форматтер и коммит не выполнялись.
  Сборка APK (T007), физический телефон (T008) и итоговая сверка (T009) открыты.
