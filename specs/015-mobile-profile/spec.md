> **Статус:** in-progress — реализация начата по явной команде пользователя 2026-11-13; T002–T006 завершены, далее T007 после ревью.

## Цель и границы

Реализовать в существующем Flutter-приложении просмотр и обновление своего
профиля через готовые GET/PUT `/api/v1/accounts/me`.
Только мобильный frontend, его тесты и документация. Серверный контракт —
[Spec 014](../014-accounts-profile/spec.md) и [OpenAPI](../../contracts/openapi/accounts-profile-v1.yaml).
Если потребуется изменить бэкенд или API, сообщить пользователю причину и
предложение, обсудить и получить отдельное согласование до изменений.
Зависимую задачу оставить открытой; независимую разрешённую работу можно продолжать.

Не входят аватары, чужие профили, история челленджей, смена email/пароля,
реализация Home/Challenges и новые серверные возможности.
Согласование требований не является разрешением на реализацию.

## Навигация и просмотр

После входа/регистрации остаётся `You are signed in`. Нижняя панель:
Home / Challenges / Profile. Home и Challenges недоступны для нажатия;
Profile справа доступен, с иконкой человека и подписью. Активный раздел выделен.
Нет обязательного заполнения профиля после регистрации. Язык UI — английский.

Профиль показывает все поля ответа, кроме version: nickname, firstName,
lastName, bio, dateOfBirth, timezone, visibility. Ник крупно, имя и фамилия
ниже; каждое значение понятно подписано. Пустые значения — `Not set`.
При незаполненных имени/описании — ненавязчивое предложение заполнить профиль.
Email не отображается, поскольку отсутствует в ответе. Кнопка `Edit profile`
открывает отдельную форму.

Справа вверху иконка выхода: меню `Sign out from this device`,
`Sign out from all devices`, `Cancel`. Сохранить существующую семантику выхода,
включая подтверждение для всех устройств и поведение при сетевой ошибке.
Выход доступен также при ошибке загрузки и выполняющемся сохранении.

## Форма и сохранение

Редактируются ник, имя, фамилия, Bio, дата рождения (выбор/очистка),
часовой пояс (список как в старом приложении) и Public/Private.
Ник и часовой пояс обязательны; имя, фамилия, Bio, дата могут быть очищены.
Часовой пояс контролируется пользователем, автоматически не меняется.
Visibility редактируется, хотя публичные страницы пока не реализованы;
не обещать существование публичной страницы.

Нормализация на телефоне выполняется перед валидацией, сравнением с исходной
формой и отправкой, а не после каждого нажатия клавиши. `Nikita   ` и `Nikita`
считаются одинаковыми при сохранении. Пробелы внутри строк сохраняются, пустые
необязательные строки становятся null; серверный strip остаётся обязательным.
Правила значений и нормализация соответствуют Spec 014. Дата передаётся без
смещения часового пояса. Ограничения Unicode соответствуют серверу.
Ошибки показываются около полей, по образцу старого UI; старые несовместимые
правила валидации не переносить. Введённые значения при ошибках не теряются.

Save без изменений закрывает форму без PUT. При изменениях отправляет полную
форму со всеми восемью ключами, nullable значениями и исходной version.
При успехе показать ответ PUT, сохранить локальную копию, вернуться в просмотр
(если пользователь ещё в форме) и показать `Profile updated`.
Уход без Save отбрасывает изменения без подтверждения. Сворачивание само по
себе не является уходом; черновик остаётся в памяти, но не сохраняется на диск.

Во время PUT переходы и назад доступны. Уже отправленный запрос продолжает
выполняться; его отмена на сервере не обещается. Повторный Save и открытие
нового редактирования заблокированы до завершения операции. При уходе черновик
отбрасывается, успех обновляет локальный профиль без принудительного перехода;
ошибка вызывает уведомление с предложением открыть профиль при необходимости.

## Загрузка и локальное хранение

Профиль, включая version, сохраняется на телефоне между запусками в защищённом
хранилище с привязкой к аккаунту. При наличии копии открытие вкладки и формы
не вызывает GET. Если копии нет — первая загрузка с индикатором.
Обновление пользователем — жест сверху вниз. При ошибке обновления сохранять
старые данные и показать сообщение. Без данных — ошибка с Retry, не пустая форма.

Исключения для GET: Reload после конфликта, проверка неопределённого результата
PUT и восстановление после завершения приложения во время PUT.
До отправки PUT сохранять признак незавершённой операции. При следующем
открытии профиля после прерывания попытаться перечитать сервер; PUT не повторять.
После неудачи проверки сохранить неопределённость и возможность повторить GET.
Ответ старого GET не должен затирать более новую версию после PUT.

При выходе удалить локальный профиль, признак операции и черновик. Ответы старой
сессии игнорировать; они не должны восстановить удалённые данные или попасть
в другой аккаунт. Профиль и токены не писать в логи.

## Ошибки и сессия

| Ситуация | Поведение |
| --- | --- |
| Занятый ник | Ошибка под nickname, значения формы сохранены. |
| Ошибки значений | Понятные сообщения по field/code около соответствующих полей. |
| Конфликт version | Сообщить об изменении на другом устройстве; блокировать повторный Save, предложить Reload profile. |
| Reload profile | По явному действию загрузить текущий профиль и заменить форму, отбросив черновик. При неудаче сохранить форму и предложить повтор. |
| Таймаут/потеря ответа PUT | Не утверждать, что сохранение не произошло. Попытаться GET; при совпадении значений с отправленными подтвердить текущее сохранённое состояние. Иначе оставить форму с сообщением о неопределённости и Reload. PUT автоматически не повторять. |
| Сессия истекла | Использовать существующее обновление сессии; при успехе продолжить операцию. При окончательной недействительности очистить профиль/черновик и показать вход. |
| Выход во время PUT | Выход разрешён, локальные данные очищены, поздние ответы игнорируются; принятые сервером изменения могут сохраниться. |

Повтор после подтверждённого отказа аутентификации отличается от слепого повтора
PUT после транспортного сбоя. Не создавать независимую ротацию refresh-токенов.
