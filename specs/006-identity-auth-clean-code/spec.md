## Цель

Сделать код входа и обновления сессии в Identity понятным для чтения и
поддержки. Клиент продолжает пользоваться теми же HTTP API и получать те же
результаты, а JWT становится обязательной частью запуска сервиса.

## Границы

### Входит в эту спецификацию

- Привести контроллеры входа и refresh, связанные сервисы и DTO к единому
  понятному стилю: HTTP в контроллере, правила в сервисе, доступ к БД в репозитории.
- Обрабатывать ошибки через существующий `ApiExceptionHandler`, убрав из
  контроллеров ручную сборку ошибок и получение `request_id`.
- Убрать режим работы Identity с выключенным JWT и связанные с ним необязательные
  зависимости, включая `ObjectProvider` там, где он больше не нужен.
- По отдельному решению владельца сделать обязательными gRPC-клиенты Accounts
  и Coins, обработчики и планировщики регистрации, а также внутренний gRPC-сервер
  проверки сессий Identity. Сохранить повторные попытки при недоступности сервисов.
- Обновить только затронутые настройки, тесты и документацию Identity.

### Не входит в эту спецификацию

- Рефакторинг всех контроллеров или других микросервисов.
- Новые методы входа, управление ролями, изменение сроков токенов или прав.
- Изменение бизнес-логики регистрации, logout, recovery, контракта ролей,
  алгоритма JWT или миграции базы.
- Развёртывание, HTTPS, Flutter и production-проверка ролей в других сервисах.

## Пользователи и права

| Участник | Ожидаемое поведение |
| --- | --- |
| Клиент | Использует существующие методы входа и refresh без изменения формата запросов и ответов. |
| Разработчик | Понимает последовательность обработки, открыв контроллер и соответствующий сервис. |
| Оператор локальной среды | Настраивает ключи JWT; при ошибке настройки видит причину неуспешного запуска без раскрытия секретов. |

## Сценарии

### Успешный вход и обновление

**Дано:** активный пользователь с действительными данными и корректно
настроенный Identity. **Когда:** клиент выполняет login или refresh.
**Тогда:** он получает прежний ответ с токенами и заголовком `Cache-Control: no-store`.
Назначенные роли и срок токенов сохраняют правила спецификации 005.

### Ошибки и граничные случаи

| Условие | Ожидаемое поведение |
| --- | --- |
| Неверные данные входа | Прежние статус, код и сообщение ошибки без раскрытия существования аккаунта. |
| Аккаунт `PENDING` или недоступен | Прежние статус и код; не выдавать токены. |
| Неверный, истёкший или отозванный refresh | Прежний ответ с ошибкой; неверный секрет сам по себе не отзывает сессию. |
| Повторно использован правильный refresh | Сессия отзывается и изменение сохраняется; клиент получает прежний ответ об ошибке. |
| Нет назначенной роли или недоступна БД | Прежние безопасные 500 или 503; частичной выдачи токенов нет. |
| Ключи JWT отсутствуют или неверны | Identity не запускается и сообщает о проблеме конфигурации без содержимого ключей. |
| Отсутствуют обязательные настройки или сертификаты gRPC | Identity не запускается; секреты в ошибку не выводятся. |
| Accounts или Coins временно недоступны | Регистрация не теряется: обработчик сохраняет состояние и повторяет временную ошибку. |

Успешные и ошибочные HTTP-ответы сохраняют действующие JSON-поля, коды,
сообщения, `request_id` и заголовки. Изменение режима выключенного JWT
согласовано отдельно: вместо частично работающего сервиса требуется настройка.

## Правила читаемости и безопасности

- Контроллер не выбирает бизнес-исход, не строит JSON ошибки и не извлекает
  `request_id`; он принимает запрос, вызывает сервис и формирует успешный HTTP-ответ.
- Названия классов и методов отражают действие: вход для активного и PENDING
  пользователя не должен называться так, будто обслуживает только PENDING.
- Внешние DTO находятся в `dto`; не возвращать внутренние результаты сервиса
  непосредственно клиенту и не плодить одинаковые DTO без необходимости.
- Применять Lombok там, где он убирает шаблонный код без потери ясности;
  не создавать дополнительные классы, обёртки и фасады только ради шаблона.
- Не менять порядок блокировок, ротацию refresh и границы транзакций. Ошибка
  после повтора refresh не должна откатывать сохранённый отзыв сессии.
- Не записывать токены, пароли, ключи и личные данные в логи или ошибки.

## Данные и конфиденциальность

Identity остаётся владельцем текущих таблиц. Изменения схемы и миграции не
требуются. Закрытый ключ и настройки доступа остаются вне Git; тесты используют
временные ключи и не меняют пользовательские локальные базы.
