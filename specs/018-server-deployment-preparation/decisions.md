# Согласованные решения dev-выкладки

Публичное описание решений. Порядок реализации задан в [plan.md](plan.md),
результаты проверок — в [verification.md](verification.md).
Индивидуальные настройки среды и операционный журнал хранятся отдельно.

## Среда

- Один тестовый VPS с Ubuntu. Высокая доступность не входит в задачу.
- PostgreSQL 17 устанавливается в ОС; Java-сервисы работают в Docker Compose.
- Java runtime входит в образ: JDK и Maven на сервере не требуются.
- Первый набор: Accounts, Coins, Identity и Gateway. Kafka и Redis добавляются
  только при появлении потребности.
- Время среды — UTC с синхронизацией. Обновления пакетов выполняются вручную
  после согласования с владельцем.

## Данные и доступ

- Каждому сервису с хранилищем выделяются своя база и роль PostgreSQL.
- Базы и роли создаются вручную; таблицы и изменения схемы — через Liquibase.
- Административное подключение к БД выполняется через SSH-туннель.
- Публичен только Gateway; внутренние сервисы и PostgreSQL не публикуются.
- Пользовательские учётные записи, адреса и параметры доступа не входят
  в публичную спецификацию.
- Реальные секреты находятся вне Git и образов. Контейнер получает только
  необходимые файлы, ключи и сертификаты с ограниченными правами.
- Серверные mTLS/JWT-материалы генерируются отдельно от сборки приложения.
  Обновление сертификатов ручное.

## Выпуск и диагностика

- Каждый сервис и gRPC-контракты имеют независимую версию. Версия общей
  библиотеки указывается явно у потребителя.
- Повышение версии сервиса в main запускает его проверку, сборку и публикацию
  точного тега в GHCR. Изменение без повышения версии не запускает выпуск.
- Изменение Compose-конфигурации сервиса требует повышения его версии.
- Первый запуск идёт по порядку Accounts → Coins → Identity → Gateway.
  При ошибке дальнейшая выкладка останавливается; автоматического отката нет.
- Настроены проверки здоровья, перезапуск контейнеров и ограничение Docker-логов.
  Диагностические дампы сохраняются вне файлового слоя контейнера.
- Неиспользуемые образы проекта очищаются после успешной выкладки;
  диагностические дампы удаляются вручную после анализа.
- Лимиты памяти уточняются по результатам первого реального запуска.

## Отложено

Отказоустойчивость, бэкапы, мониторинг, уведомления, домен и HTTPS,
доступ будущих участников команды и перенос БД на другой сервер.
Эти ограничения относятся к согласованной тестовой среде.
