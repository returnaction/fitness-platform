# План: заготовки микросервисов

> **Спецификация:** [spec.md](spec.md)  
> **Статус:** implemented

## Решение

Использовать существующий корневой POM и версии проекта. Каждый модуль —
Spring Boot приложение с Web MVC, Security и Actuator; HTTP-доступ ограничен служебными endpoints Actuator; все остальные запросы закрыты.
Порт задаётся `SERVER_PORT`, готовый пример — в `.env.example`; локальный
профиль подключает его и необязательный `.env`. Для теста используется порт 0.
Не добавлять PostgreSQL и миграции до появления согласованной задачи с данными.
Общие HTTP-классы размещаются в `shared.web`, настройки безопасности —
в `security.config`; стартовый класс остаётся в корневом пакете сервиса.
Для каждого нового сервиса предусмотреть Dockerfile и тестовый профиль
`test`; Dockerfile Identity, Accounts и Coins также учитывают POM новых модулей.

## Проверка

Запустить `mvnw verify` для корня, включая тесты, форматирование и анализ.
Собрать пять Docker-образов из корня проекта. Проверить, что Maven видит все пять модулей; ручной импорт в IntelliJ отмечать
только после фактической проверки. Не считать автоматически запущенный тест
доказательством проверки в IntelliJ.

## Риски

Другая ветка может изменить корневой POM; при интеграции сохранить оба набора
модулей. Порты примеров уникальны относительно известных сервисов, но их
доступность на компьютере заранее не гарантируется.

Сетевые ограничения management endpoint на сервере выполняются отдельно
и не входят в рамки этой спецификации.
