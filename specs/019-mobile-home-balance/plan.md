# План реализации: мобильный Home с балансом

> **Спецификация:** [spec.md](spec.md)
> **Статус:** implemented
> **Связанные документы system-design:** [Coins wallet](../../system-design/services/coins/33-coins-wallet-and-reward.md),
> [Gateway access](../../system-design/architecture/access/15-auth-gateway-draft.md)

## Краткое решение

Добавить в Flutter отдельные model/repository/controller/screen для
read-only снимка кошелька и сделать Home активной вкладкой существующего
`AppShellScreen`. Экран повторяет размещение старого Flutter-клиента: баланс
находится в правой части `AppBar` как два компактных индикатора, разделённых
вертикальными линиями (монета/доступно и замок/зарезервировано). Repository вызывает установленный контракт через
`IdentityApiClient` и `AuthRepository.authenticatedRequest`, поэтому повторное
получение access token и реакция на завершение сессии остаются общими с
профилем. `WalletStore` записывает последний валидный снимок в существующее
защищённое хранилище вместе с accountId. Home сначала читает этот снимок, если
он принадлежит текущей сессии, а потом выполняет один GET для уточнения.

## Затрагиваемые границы

| Область | Изменение | Владелец данных / контракта |
| --- | --- | --- |
| Flutter Home | Экран, состояние, форматирование `int64`, загрузка и Retry | мобильный клиент |
| Flutter auth | Переиспользование существующего authenticated request и session generation | мобильный клиент |
| Gateway → Coins | Без изменений: GET `/api/v1/coins/me` | Coins владеет контрактом и кошельком |

## Данные и миграции

Новых таблиц, миграций и серверных данных нет. Клиентское защищённое хранилище
содержит `accountId` и последний успешный `WalletBalance`; несовпадающая или
повреждённая запись удаляется. Модель `WalletBalance` проверяет два
неотрицательных целых `int64` из JSON. GET не изменяет кошелёк, поэтому ключ
идемпотентности и транзакционная логика клиенту не нужны.

## Контракты и взаимодействия

| Направление | Тип | Изменение | Версионирование / совместимость |
| --- | --- | --- | --- |
| Flutter → Gateway → Coins | REST | Использовать существующий `GET /api/v1/coins/me` с Bearer | OpenAPI v1 без изменения |

Авторизация, поля, успешный пример, `401`, `500`, `503`, `Cache-Control` и
`X-Request-Id` определены владельцем в
[coins-wallet-v1.yaml](../../contracts/openapi/coins-wallet-v1.yaml).
Приложение не добавляет заголовков с user ID и не обращается к Coins напрямую.

## Надёжность и безопасность

- `AuthRepository.authenticatedRequest` обеспечивает согласованный refresh и
  передаёт окончательный сбой сессии в `AuthController`.
- Контроллер дедуплицирует запросы, использует generation сессии и игнорирует
  поздний ответ после logout или смены пользователя. Снимок удаляется при
  очистке сессии, а также не используется для другого accountId.
- Ошибки HTTP и разбора ответа показываются пользователю нейтрально; баланс,
  токены, request ID и тело ошибки не журналируются.
- Ни автоматических повторов GET, ни фонового polling нет. Пользователь
  выполняет явный Retry или pull-to-refresh.

## Проверка

- Unit: строгий JSON-разбор, границы `int64`, неотрицательность и форматирование.
- Repository/controller/store: Bearer, `401` с существующим refresh, ошибки,
  показ сохранённого снимка до сети, account isolation, дедупликация, reset
  при смене сессии и поздний ответ.
- Widget: Home в навигации; AppBar со spinner, двумя индикаторами баланса,
  кнопкой повторной загрузки при ошибке и подсказками; refresh и Retry.
- Итог: `flutter analyze`, `flutter test`, debug APK и `git diff --check`.
- Ручная проверка на эмуляторе или телефоне требует доступных Gateway, Identity
  и Coins; отсутствие такой среды фиксируется как ограничение, а не как успех.

## Риски и решения

| Риск или открытый вопрос | Решение / кто принимает решение |
| --- | --- |
| Старое Python-представление баланса недоступно | Пользователь подтверждает предложенный минимальный UI либо уточняет его до реализации. |
| Dart web `int` может потерять точность | Целевой клиент — Android; модель всё равно проверяет диапазон контракта и не использует `double`. |
| Данные устаревают после открытия | Это допустимо для v1: только явное обновление; realtime вынесен из scope. |
