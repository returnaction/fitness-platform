## Покрытое поведение

- Модель принимает только неотрицательные целые значения, представимые в
  `int64`, и форматирует группы разрядов без преобразования в `double`.
- Repository вызывает только Gateway `GET /api/v1/coins/me` с Bearer; проверен
  один согласованный refresh после `401`.
- Controller проверяет первый GET, Retry, дедупликацию одновременных запросов,
  очистку при смене сессии и игнорирование позднего ответа. Отдельный тест
  подтверждает показ сохранённого снимка до завершения свежего GET.
- Widget проверяет доступный и зарезервированный баланс с подсказками в правой
  части AppBar. Зависимые auth/profile UI-тесты обновлены, потому что успешный
  вход теперь открывает Home вместо временного `You are signed in` экрана.

## Реальная USB-проверка

- Подключённый пользовательский телефон SM-S938B был авторизован через ADB.
  Выполнен `adb reverse tcp:8088 tcp:8088`.
- Локальные Accounts, Coins, Identity и Gateway версии 0.1.1 запущены с
  существующими local-конфигурациями. Gateway health вернул 200; защищённый
  Coins route без токена вернул ожидаемый 401 до проверки телефона.
- Debug APK собран с
  `API_BASE_URL=http://127.0.0.1:8088`, установлен поверх существующего
  приложения с сохранением данных, затем пользователь выполнил вход.
- Home реально открылся на телефоне: в AppBar отображались доступный и
  зарезервированный баланс `0` и `0`. После pull-to-refresh значения остались
  видимыми, экран ошибки не появился.
- После замены Home на `FutureProvider.autoDispose` (как в старом Flutter
  клиенте) тот же телефон подтвердил первый успешный показ `0`/`0` без
  перехода в Profile. При повторном USB-подключении `Cannot connect` был
  вызван отсутствующим `adb reverse`; после восстановления
  `tcp:8088 -> tcp:8088` Gateway снова стал доступен приложению.

## Ограничения

- Изменение с защищённым кэшем ещё не повторено на физическом телефоне: он
  отключён пользователем после сообщения об исходной проблеме. Нужны новая
  APK-установка и проверка: завершить успешную загрузку, закрыть/открыть Home
  и убедиться, что старые числа видны до ответа Gateway.
- Значения в тестовом кошельке были нулевыми. Недоступность сети/Coins и
  окончательная потеря сессии на физическом телефоне в этой сессии намеренно
  не инъецировались; они покрыты автоматическими тестами.
- Коммит, push, merge, deploy и миграции пользовательских БД не выполнялись.
