## Цель

Дать вошедшему пользователю простой Home-экран, на котором он видит свой
текущий баланс виртуальных монет. Экран использует уже реализованный маршрут
`GET /api/v1/coins/me` через API Gateway и не добавляет финансовых операций.

## Границы

### Входит в эту спецификацию

- Включить пункт Home в существующей нижней навигации Flutter после входа.
- Загрузить и показать баланс в правой части `AppBar` Home, как в старом
  Flutter-клиенте: иконка монеты и `availableBalance`, разделитель, иконка
  замка и `lockedBalance`.
- Сохранить последний успешный снимок двух сумм в защищённом хранилище,
  привязав его к аккаунту; сразу показать его при повторном открытии Home и
  затем запросить актуальное значение.
- Обработать загрузку, ручный повтор и pull-to-refresh без показа выдуманного
  числового значения. При неудачном обновлении разрешено оставить явно
  сохранённый предыдущий снимок.
- Использовать существующий session-aware HTTP-путь: Bearer, один
  скоординированный refresh при `401` и существующий переход к входу при
  окончательной потере сессии.
- Добавить unit/widget-тесты и обновить мобильную документацию и доказательства
  проверки.
- Подготовить следующую задачу: история ранее использованных аккаунтов на
  форме входа с безопасным хранением и подстановкой email и пароля после
  выбора аккаунта.

### Не входит в эту спецификацию

- Изменение Coins, Gateway, OpenAPI или PostgreSQL; контракт уже существует.
- Начисление, списание, резервирование, история операций, ставки и settlement.
- WebSocket, polling в фоне и push-обновления баланса.
- Реализация Challenges, каталога упражнений и других Home-виджетов.
- Изменение регистрации, профиля, токенов или механизма logout.

## Пользователи и права

| Роль | Что может делать |
| --- | --- |
| Вошедший пользователь | Открыть Home и увидеть только баланс кошелька своего `sub`. |
| Неавторизованный пользователь | Не видит Home: существующий AuthGate показывает вход. |
| Gateway и Coins | Проверяют access token и сессию; клиент не передаёт user ID. |

## Сценарии

### Сценарий: пользователь открывает Home

**Дано:** пользователь вошёл; при предыдущем успешном запросе мог быть
сохранён снимок его баланса.
**Когда:** он открывает Home после входа или возвращается на него.
**Тогда:** приложение сразу показывает сохранённый снимок, если он есть, и
параллельно запрашивает `GET /api/v1/coins/me` с текущим Bearer токеном.
После успеха оно заменяет снимок актуальным значением. В правой части `AppBar`
показаны две компактные пары
«иконка + целое число»: доступные и зарезервированные виртуальные монеты.
Подсказки иконок — `Available coins` и `Locked coins`.

### Сценарий: пользователь обновляет баланс

**Дано:** на Home уже показан успешный снимок.
**Когда:** пользователь тянет экран вниз или нажимает Retry после ошибки.
**Тогда:** выполняется один новый GET; до успешного ответа старые числа могут
оставаться на экране с индикатором обновления. Если первого успешного снимка
нет, вместо чисел показывается только индикатор либо ошибка.

### Ошибки и граничные случаи

| Условие | Ожидаемое поведение для клиента |
| --- | --- |
| Нет сети, 5xx, `coins_unavailable` или невалидный JSON | Если снимка нет — понятное нейтральное сообщение `Could not load balance.` и Retry. Если есть сохранённый снимок — он остаётся видимым, а ответ и ошибка не попадают в логи. |
| `401` | Используется существующий единичный refresh. При окончательном отказе существующая логика очищает сессию и показывает вход. |
| `500 wallet_invariant_violation` | Не показывать нулевой баланс; показать то же нейтральное сообщение и Retry. |
| Повторное нажатие/обновление во время GET | Не запускать параллельный второй запрос. |
| Logout или смена сессии во время GET | Удалить сохранённый снимок, сбросить состояние Home; поздний ответ старой сессии игнорировать. |
| Значение до `int64` maximum | Разобрать без потери точности и показать как целое число с группировкой разрядов; отрицательные и иные некорректные значения считать ошибочным ответом. |

## Бизнес-правила

- Coins остаётся единственным источником истины: приложение только читает
  снимок, не суммирует и не вычисляет доступный баланс.
- Доступный и зарезервированный баланс не складываются в «общий баланс»: первый
  — доступная сумма, второй уже зарезервированная.
- GET безопасно повторяется; после показа сохранённого снимка выполняется один
  запрос уточнения, но автоматических периодических запросов нет.
- Сервер определяет владельца по токену; параметр идентификатора пользователя
  и путь к чужому кошельку не добавляются.

## Данные и конфиденциальность

Приложение сохраняет только `accountId`, `availableBalance` и `lockedBalance`
последнего успешного ответа в уже используемом зашифрованном
`flutter_secure_storage`. Данные не передаются в логи и не включаются в
сообщения об ошибках. При несовпадении accountId, повреждённой записи, logout
или окончательной потере сессии снимок удаляется. Access и refresh tokens
продолжают обрабатываться существующим кодом сессии.

## Критерии готовности

- [x] Home доступен в нижней навигации только в аутентифицированной оболочке.
- [x] При успешном ответе в правой части AppBar отображаются доступный и
  зарезервированный баланс текущего пользователя без потери точности `int64`.
- [x] Последний снимок текущего аккаунта показывается до ответа сети, а
  ответ другого аккаунта или устаревшая операция не могут его восстановить.
- [x] Первый запрос, refresh, ошибки, Retry и защита от параллельных GET
  ведут себя согласно этой спецификации.
- [x] Logout, окончательная потеря сессии и поздний ответ старой сессии не
  раскрывают баланс другому пользователю.
- [x] Автоматические Flutter-проверки, analyze и debug APK успешно выполнены;
  результаты и ограничения записаны в `verification.md`.

## Открытые вопросы

- Старый Flutter-клиент подтверждает расположение баланса; его ежедневная
  награда и содержимое списка активных challenges не переносятся, поскольку
  соответствующие Java-контракты и функции не входят в эту спецификацию.
