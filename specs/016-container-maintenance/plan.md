> **Стандарты:** [engineering-standards](../../docs/engineering-standards.md).

1. Перед реализацией перечитать все девять Dockerfile из таблицы spec.md, root pom,
   конфигурацию сборки и [документы развёртывания](../../system-design/architecture/deployment/README.md).
   Проверить реальные версии базовых образов и их пользователя. Найденные
   посторонние проблемы записать отдельно, не расширять задачу автоматически.
2. После разрешения закрепить JDK/JRE 25.0.5_8 и UID 10001 в финальных образах.
   Проверить владельцев/доступ к jar и рабочим каталогам; сохранить ручное
   форматирование и существующий способ запуска. Актуализировать связанные пояснения при наличии; уже правильные настройки сохранить.
3. Собрать все девять образов, проверить версии Java обоих этапов, metadata USER и id -u.
   Выполнить проверку Java-процесса и readiness при необходимых зависимостях.
   Перед запуском определить доступную проверочную среду, не создавать серверное
   развёртывание и не запускать миграции пользовательских БД.
4. Записать команды, результаты, ограничения и проверить критерии spec.md.
   Проверить Markdown штатным scripts/verify-markdown-links.ps1.

В T003 проверены базовые JDK/JRE, сервисные образы ещё не собирались. Состав проверочной среды пока не выбран;
это не блокирует подготовку документов. Изменения API и миграции не ожидаются.
