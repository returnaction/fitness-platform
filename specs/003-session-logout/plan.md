# План реализации: выход из сессии

> **Спецификация:** [spec.md](spec.md)
> **Статус:** implemented
> **Связанные документы system-design:** [сессии Identity](../../system-design/services/identity/31-identity-login-sessions.md), [проверка сессии](../../system-design/interactions/59-identity-accounts-internal-api.md)

## Краткое решение

Добавить два HTTP-сценария в Identity, используя
существующие сессии PostgreSQL. Logout API реализован, а Spring
Security разрешает только явно перечисленные auth-маршруты. Для logout-all
нужна проверка обычной пользовательской сессии: существующий фильтр восстановления
предназначен для административного сценария и требует отдельной роли.

## Затрагиваемые границы

| Область | Изменение | Владелец данных / контракта |
| --- | --- | --- |
| Identity | HTTP, проверка токенов и отзыв сессий | Identity |
| Контракты | OpenAPI ошибок и запросов, примеры Postman | Identity |
| Другие сервисы | Локально проверять JWT в будущих защищённых API; немедленный отзыв access не гарантирован | Соответствующий сервис; изменения за пределами Identity отдельно согласовать |

## Данные и миграции

- Использовать существующие `auth_sessions` и `refresh_tokens`; необходимость
  миграции и индексов проверить по текущей схеме, не предполагать заранее.
- Сессии принадлежат Identity. Отзыв и конкурирующие обновления выполняются
  транзакционно; повтор logout не раскрывает, существует ли токен.
- Использовать блокировку строки пользователя как общую точку сериализации
  logout-all и создания сессий. После её получения перепроверить авторизацию и
  отозвать сессии внутри транзакции. Порядок существующего refresh —
  `user → session → token`; совместимость с созданием сессий регистрации,
  входом и остальными путями проверить, избегая взаимных блокировок.
- Аудит исходного кода и оставшиеся конкурентные проверки описаны в
  [lock-analysis.md](lock-analysis.md); порядок регистрации и фоновой активации
  требует отдельного доказательства на PostgreSQL.
- Не применять миграции к пользовательской БД без разрешения.

## Контракты и взаимодействия

| Направление | Тип | Изменение | Совместимость |
| --- | --- | --- | --- |
| Клиент → Identity | HTTP | Logout с refresh и logout-all с Bearer; `204`, ошибки из spec | Дополнение v1 OpenAPI до реализации |
| Сервисы → Identity | gRPC | Существующий `CheckSession` сохраняется для сценариев, где он нужен | Вызов при каждом запросе не требуется; локальная проверка JWT не видит отзыв сессии |

Операции, JSON, авторизация, ошибки и лимиты описаны в
[OpenAPI](../../contracts/openapi/identity-auth-v1.yaml).
Изменения других сервисов не входят
в текущий объём.

## Надёжность и безопасность

- Для logout-all в Identity проверять подпись, срок, issuer, audience и
  актуальную сессию; refresh проверять по полному секрету, а не только идентификатору.
- Сохранить существующую политику повторного использования refresh и ответов;
  не удерживать транзакцию во время сетевого вызова.
- Не записывать токены и персональные данные в логи и ответы ошибок.
- Проверять отказ БД и отсутствие ложного подтверждения выхода. Для logout
  и logout-all применять отдельные лимиты по 30 запросов в минуту с IP.
- Для logout проверять секрет даже у использованного refresh: правильный
  секрет позволяет отозвать связанную сессию, неправильный — нет.

## Проверка

- Unit: проверка токенов, правила повтора, ошибки и права.
- PostgreSQL integration: отзыв, миграция при необходимости, rollback,
  параллельные logout/refresh, несколько сессий и logout-all/login.
- HTTP и gRPC: коды, JSON, проверки авторизации и `CheckSession` до/после
  отзыва, безопасные логи; отдельно проверить, что локальная проверка JWT
  без проверки сессии не обнаруживает отзыв до истечения срока.
- Локально: запросы Postman, после чего полная Maven-сборка и необходимые
  интеграционные тесты; пользовательские базы не изменять автоматически.

## Риски и решения

| Риск или открытый вопрос | Решение / кто принимает решение |
| --- | --- |
| Access JWT не отзывается одной проверкой подписи | Принято владельцем: для локальной проверки возможен доступ до истечения срока токена. |
| Logout-all пересекается с новой сессией | Сериализация по блокировке пользователя; проверить оба порядка PostgreSQL-тестом. |
| Потерян ответ logout-all | Отозванный токен не даёт авторизовать повтор; зафиксировать путь клиента. |
