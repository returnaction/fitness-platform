# Решения и открытые вопросы Spec 013

## Q001 — среда: частично решено

- Задачи: T002–T004, T008.
- Решение пользователя 2026-11-12: локально отдельные процессы без контейнеров;
  на сервере позже контейнеры.
- Локальное решение: внутренние listeners на loopback плюс mTLS и права операций.
- Осталось для T008: топология контейнеров/серверов, правила публикации и firewall,
  доступ мониторинга. Варианты зависят от реальной платформы запуска.
- Рекомендация: не публиковать внутренние порты наружу, дать Gateway сетевой
  доступ только к нужным интерфейсам; проверить из внешней и внутренней сети.
- Заблокирован только серверный rollout; локальное проектирование продолжается.

## Q002 — recovery и диагностика: ближайшее решение

- Задачи: T002, T004, T008.
- Доказательство: recovery использует AccessTokenVerifier, активную сессию и
  SUPER_ADMIN из БД. Пользователь сообщил, что сейчас им не пользуется.
- Ближайшее решение: закрыть recovery по умолчанию, не удалять механизм и его
  бизнес-проверки. Gateway не получает права recovery. Административный доступ
  будет включаться отдельно после определения оператора и его способа работы.
- Рекомендация для будущего: отдельный сертификат оператора плюс существующая
  JWT-проверка; это не утверждённый административный клиент.
- Management локально на отдельном loopback listener, без публикации в Gateway.
  Для контейнерного этапа определить реальные probes/метрики и их callers.
- Блокируется включение удалённого административного доступа и мониторинга;
  локальные этапы с закрытым recovery не блокируются.

## Q003 — Content-Encoding: отложено пользователем

- Доказательство: ForwardedHeadersFilter не переносит Content-Encoding;
  Spec 012 содержит такой же allowlist. Воспроизводящий gzip-тест не выполнялся.
- Решение пользователя 2026-11-12: сейчас не делать ни проверку, ни исправление;
  вернуться к вопросу, когда появятся такие запросы.
- Вариант 415 без распаковки не согласован и не реализуется в Spec 013.
- Риск сохранён как незакрытый, не считается исправленным; текущие задачи не блокирует.

## Итог grilling — согласован 2026-11-12

Пользователь подтвердил общее понимание и разрешил обновить только документацию.
Номера G ниже соответствуют номерам вопросов в чате, не Q001–Q003 выше.

| Решение | Итог | Задачи |
| --- | --- | --- |
| G1: доверие Gateway | Gateway — доверенный аутентификатор; mTLS не защищает от захвата самого Gateway с его ключом | T002–T005 |
| G2: снятие ролей | Допустимо сохранение старых прав до истечения access, максимум 15 минут. Refresh читает роли из БД; старый токен не меняется. Recovery сохраняет проверку SUPER_ADMIN в БД | T005–T006 |
| G3: сертификаты | Замена с перезапуском, короткий перерыв допустим; без hot reload и fallback на HTTP | T003–T004 |
| G4: роли logout-all | Собственные сессии можно закрыть без известных ролей; повреждённый контекст отклоняется; USER по умолчанию нет | T005–T006 |
| G5: межсервисные вызовы | Напрямую, с отдельными правами на операции. Accounts не нужен logout-all; чужой caller всё равно не должен иметь к нему доступ | T002–T004 |
| G6: отзыв исходной сессии после Gateway | Не отменяет уже допущенный logout-all; закрыть все сессии, уже закрытые — 204 | T005–T006 |
| G7–G8: проверка | Запускать локальное приложение пользователя, отдельный стенд не нужен; разрешено создать тестового пользователя через API | T004, T006 |
| G9: истечение токена после Gateway | Завершить уже допущенный logout-all; повторный отказ по exp убрать | T005–T006 |
| G10: конкурентные запросы | Не выделять в новое продуктовое решение; обеспечить необходимые транзакции и блокировки, проверить гонки | T005–T006 |
| G11: блокировка пользователя после Gateway | Не мешает закрыть сессии; требование ACTIVE для выполнения этой команды убрать | T005–T006 |

G6/G9/G11 заменяют первоначальное предложение сохранить повторные отказы в
LogoutService. Момент допуска — успешная проверка JWT и CheckSession в Gateway.
До допуска проверки сохраняются. При техническом сбое нельзя объявлять успешный
отзыв; доставка команды и получение ответа не гарантируются этим решением.
Новый внешний запрос проходит проверки Gateway заново.

Основание проверки G2: RefreshTokenService вызывает UserRoleRepository перед
AccessTokenSigner; срок access не более 900 секунд, обычный refresh не отзывает
старый access. Это чтение кода, не новый результат запуска тестов.

Решения локального этапа согласованы. Открытые инфраструктурные детали Q001/Q002
касаются будущего серверного запуска, а Q003 отложен. Реализация ждёт отдельной
команды пользователя; серверные действия и миграции не разрешены.

## Дополнительное решение — удалить rate limiter Identity

Пользователь 2026-11-12 явно запросил удаление всего механизма ограничения
частоты auth-запросов и связанных тестов. Задача T002a: удалить подключения,
классы, настройки, зависимости и актуализировать контракт Identity. JWT/mTLS
и бизнес-операции не входят в удаление; перенос limiter в Gateway не запрошен.
После проверки остановиться без коммита. Это согласованное изменение требований.
