# План Spec 013

> **Статус:** согласованный локальный объём завершён, включая T007. Результаты — в tasks.md и verification-t006.md.
> **Основание:** [спецификация](spec.md), [задачи и проверки](tasks.md), [текущая схема](current-state.md).

## Выполненный локальный этап

1. T002: ограничены локальные listeners, разделены API/management Identity,
   закрыт recovery. Первоначальная HTTP mTLS-защита впоследствии отменена.
2. T002a: удалён rate limiter Identity, его настройки, зависимости и тесты.
3. T002b: Identity возвращён на HTTP без сертификатов. Сохранены loopback,
   allowlist операций, разделение management, закрытый recovery, полная проверка
   JWT и текущие бизнес-проверки logout-all. Существующий gRPC mTLS не менялся.
4. Документы согласованы с HTTP: отменённые требования не являются очередью работ.

Объём проверок каждого изменения указан в tasks.md. Полный бизнес-набор после
T002b не перезапускался; прежние TLS-проверки не доказывают защиту текущего HTTP.

## Дальнейшие этапы — Identity logout-all

T003 (HTTP mTLS в Gateway) отменён и не блокирует эти задачи. Для локального
HTTP принято доверие к тому, что пользовательский запрос прошёл Gateway;
техническое подтверждение caller и подготовка Docker в этот этап не входят.

1. T004: перед изменением сверить текущий HTTP-путь и точки повторной проверки:
   Gateway JWT/CheckSession → LogoutAllAuthenticationFilter → LogoutController →
   LogoutService. Проверить использования AccessTokenVerifier, существующие
   тесты и пользовательские изменения. Зафиксировать исходное поведение;
   это подготовка к реализации, а не TLS/security gate.
2. T005: убрать повторную JWT-криптографию только для logout-all, извлекать
   необходимый ID из токена. Роли для отзыва сессий не нужны. SecurityContext
   сохранить с UUID principal без ролей по последнему решению пользователя.
   Убрать повторные отказы по exp, исходной сессии и блокировке пользователя
   после допуска Gateway. Сохранить атомарность отзыва, необходимые блокировки,
   обработку ошибок и отдельную JWT-проверку административного recovery.
3. T006: проверить новое поведение и ошибки, транзакции и гонки, а также отсутствие
   регрессий register/login/refresh/logout. Проверить реальное локальное приложение
   пользователя по HTTP, включая JWKS/readiness и внутренние gRPC-вызовы.
4. T007: завершить проверки Maven, Spotless/SpotBugs, актуализировать контракты
   и записать результаты с ограничениями. Не объявлять серверную защиту готовой.

Критерии задач находятся в tasks.md. Пользователь разрешил реализацию logout-all
и проверку тестами с сохранением SecurityContext. После каждого пункта
остановиться для проверки пользователем, без коммита агента.

## Границы работы и проверки

Серверный запуск в Docker не подготавливать: его конфигурация, сеть и план запуска
не входят в текущий объём. T008 исключён из текущего плана. Content-Encoding,
подключение Accounts/Coins к пользовательским маршрутам и административный
клиент также отложены.

Для T005 выполнены Maven verify Identity, Spotless и SpotBugs; результаты
зафиксированы в tasks.md. Ссылки и git diff --check проверены. Для дальнейших
изменений использовать существующие Maven Wrapper и необходимые тесты. Реальное локальное приложение проверять без
отдельного стенда; миграции пользовательских БД без разрешения не запускать.
После каждого пункта остановиться для ревью; коммит выполняет пользователь.
