### T005 — Создать миграцию `catalog_categories`

**Предусловие:** T004 завершена: Liquibase уже подключён к пустой тестовой
PostgreSQL-базе.

**Создать файлы:**

```text
db/changelog/changes/001-create-catalog-categories.yaml
db/changelog/changes/001-create-catalog-categories.sql
```

Подключить YAML в `db.changelog-master.yaml`. YAML содержит один changeset
`001-create-catalog-categories`, а SQL — только создание таблицы и её индекса.

**В SQL создать только эту таблицу:**

| Колонка | Точный тип и ограничение |
| --- | --- |
| `id` | `SMALLINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY CHECK (id BETWEEN 1 AND 32767)` |
| `code` | `VARCHAR(64) NOT NULL UNIQUE` |
| `name` | `VARCHAR(120) NOT NULL` |
| `is_active` | `BOOLEAN NOT NULL` |
| `sort_order` | `INTEGER NOT NULL CHECK (sort_order >= 0)` |
| `version` | `BIGINT NOT NULL CHECK (version > 0)` |
| `created_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |

Создать индекс `(is_active, sort_order, id)`. `code` проверяется приложением
по regex `^[A-Z][A-Z0-9_]{0,63}$`; SQL-миграция не должна добавлять упражнения,
вариации или seed-данные.

**Проверить:** на чистой PostgreSQL Liquibase применяет changeset; повторный
старт не применяет его второй раз; `code` не дублируется, ID вне диапазона,
отрицательный `sort_order` и `version = 0` отклоняются базой.

**Готово:** есть PostgreSQL-интеграционный тест, проверяющий таблицу, индекс и
все перечисленные ограничения.

### T006 — Создать миграцию `catalog_exercises`

**Предусловие:** T005 завершена. Не создавать данные категории: это T008.

**Создать файлы:**

```text
db/changelog/changes/002-create-catalog-exercises.yaml
db/changelog/changes/002-create-catalog-exercises.sql
```

Подключить YAML после changeset `001`.

**В SQL создать только эту таблицу:**

| Колонка | Точный тип и ограничение |
| --- | --- |
| `id` | `SMALLINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY CHECK (id BETWEEN 1 AND 32767)` |
| `category_id` | `SMALLINT NOT NULL REFERENCES catalog_categories(id) ON DELETE RESTRICT` |
| `code` | `VARCHAR(64) NOT NULL UNIQUE` |
| `name` | `VARCHAR(120) NOT NULL` |
| `description` | `VARCHAR(1000) NOT NULL` |
| `primary_metric` | `VARCHAR(16) NOT NULL CHECK (primary_metric IN ('REPETITIONS', 'DURATION'))` |
| `is_active` | `BOOLEAN NOT NULL` |
| `sort_order` | `INTEGER NOT NULL CHECK (sort_order >= 0)` |
| `version` | `BIGINT NOT NULL CHECK (version > 0)` |
| `created_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |

Создать индекс `(category_id, is_active, sort_order, id)`. Не создавать
вариации, REST endpoint, gRPC или seed-данные.

**Проверить:** PostgreSQL не разрешает создать упражнение с отсутствующей
категорией, удалить категорию с упражнением, повторить `code`, указать ID вне
диапазона, другую метрику или отрицательный `sort_order`.

**Готово:** есть PostgreSQL-интеграционные тесты FK, unique и всех checks.

### T007 — Создать миграцию `catalog_variations`

**Предусловие:** T006 завершена. Не создавать стартовые записи: это T008.

**Создать файлы:**

```text
db/changelog/changes/003-create-catalog-variations.yaml
db/changelog/changes/003-create-catalog-variations.sql
```

Подключить YAML после changeset `002`.

**В SQL создать только эту таблицу:**

| Колонка | Точный тип и ограничение |
| --- | --- |
| `id` | `SMALLINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY CHECK (id BETWEEN 1 AND 32767)` |
| `exercise_id` | `SMALLINT NOT NULL REFERENCES catalog_exercises(id) ON DELETE RESTRICT` |
| `code` | `VARCHAR(64) NOT NULL` |
| `name` | `VARCHAR(120) NOT NULL` |
| `description` | `VARCHAR(1000) NOT NULL` |
| `instructions` | `VARCHAR(2000) NOT NULL` |
| `min_target` | `BIGINT NOT NULL CHECK (min_target > 0)` |
| `max_target` | `BIGINT NOT NULL CHECK (max_target >= min_target)` |
| `target_step` | `BIGINT NOT NULL DEFAULT 1 CHECK (target_step > 0)` |
| `is_active` | `BOOLEAN NOT NULL` |
| `sort_order` | `INTEGER NOT NULL CHECK (sort_order >= 0)` |
| `version` | `BIGINT NOT NULL CHECK (version > 0)` |
| `created_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP` |

Создать `UNIQUE (exercise_id, code)` и индекс
`(exercise_id, is_active, sort_order, id)`. Не реализовывать правило
`STANDARD`: без admin API оно доказывается стартовыми данными в T008, а не
триггером этой миграции.

**Проверить:** PostgreSQL отклоняет неизвестное упражнение, второй одинаковый
code одного упражнения, ID вне диапазона, нулевые/отрицательные границы и шаг,
`max_target` меньше `min_target`.

**Готово:** есть PostgreSQL-интеграционные тесты FK, unique и всех checks.

Тексты инструкций задают условия для первого MVP, но не являются полными
медицинскими рекомендациями или автоматическими критериями оценки техники.
Подтягивания, скручивания, выпады, боковая планка и дополнительные вариации
намеренно не входят в этот стартовый changeset: их добавляют новым changeset
после отдельного согласования.

**Проверить:** чистая база получает согласованный набор данных; все активные
упражнения имеют активный `STANDARD`; все значения удовлетворяют constraints;
повторный запуск Liquibase не создаёт дубликаты.

**Готово:** seed-данные прошли PostgreSQL-интеграционный тест и сверены с
утверждённой таблицей стартового каталога.

**Владелец:** senior. До T011 описать непрозрачный cursor, его привязку к

- [ ] **T011 — Реализовать API списка упражнений.** Фильтр категории, limit,

- [ ] **T012 — Реализовать карточку упражнения.** `GET /api/v1/exercises/{id}`:
  метрика, единица, активные вариации, инструкция и пределы; `404` для
  неизвестного или выключенного упражнения.

### D003 — Зафиксировать внутренний доступ Gateway → Catalog

**Владелец:** senior / команда платформы. Определить, как Gateway удостоверяет
себя перед Catalog во внутренней сети. Пользовательский JWT уже проверяет
Gateway и не передаётся в Catalog как основание для решения.

- [ ] **T013 — Интегрировать Catalog с Gateway.** Catalog не валидирует JWT
  пользователя. Закрыть его REST-порт от внешнего доступа, разрешить только
  Gateway по механизму из D003, проверить отсутствие прямого доступа. Catalog
  возвращает только свои `404`/`422` и безопасно логирует ошибки; `401` —
  ответственность Gateway.
