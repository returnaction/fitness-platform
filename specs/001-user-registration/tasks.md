Сверка критериев локальной базы: `IdentitySchemaMigrationIntegrationTest`
проверяет миграции, уникальность email и откат; `RegistrationServiceIntegrationTest`
проверяет конкурентные операции, аренду и откаты; интеграционные тесты
Accounts и Coins проверяют ограничения и повторное создание профиля/кошелька.
Примеры REST и gRPC находятся в [OpenAPI](../../contracts/openapi/identity-auth-v1.yaml)
и [описании контрактов](../../contracts/README.md).

Сверка безопасности локального сценария: HTTP-ошибки `400`, `401`, `409`,
`422`, `429`, `500`, `503`, ошибки внутренних gRPC-вызовов и PostgreSQL, а
также журналы трёх сервисов проверены тестами с контрольными значениями.
Сообщения исключений фонового обработчика и контроллера проверены отдельно.
События Kafka при регистрации не создаются. Проверка относится к указанным
сценариям и не заменяет проверку новых сценариев при их добавлении.

Локальная итоговая проверка 2026-11-08: `mvnw verify` прошёл для всех трёх
сервисов и контрактов; сквозной сценарий с локальными сертификатами step-ca
прошёл отдельно. Критерии `spec.md` проверены; изменения локального сценария
влиты в `main` через PR [#21](https://github.com/returnaction/fitness-platform/pull/21).

Текущий прогресс: сквозной тест проверяет три процесса и временные базы с mTLS,
недоступность зависимостей, вход в `PENDING`, перезапуск Identity, повтор
`503` → `201`, профиль, кошелёк, сессии и одновременные запросы.
Он использует отдельную временную CA, а не step-ca. Также проверены сбой
Identity при активной аренде и ожидающем ответ gRPC-вызове, а затем
восстановление без дубликатов. Гонка при создании регистрации также проверена
интеграционным тестом с синхронизацией после проверки email. Перечисленные в
плане сбои и гонки проверены. Отдельно проверена задержка gRPC-ответов
Accounts и Coins после commit: Identity видит таймаут и завершает регистрацию
повтором без дубликатов. Для повторения теста нужны Docker, Python 3,
OpenSSL и JDK 25. Из корня проекта в PowerShell:

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress -DskipTests package
python scripts/verify-registration-e2e.py
```

Тест запускает временный PostgreSQL-контейнер и отдельные процессы сервисов,
создаёт временные сертификаты и завершает их после проверки. Локальные базы и
существующие сертификаты проекта он не использует.

Локальные сертификаты step-ca отдельно проверены тем же сквозным сценарием с
параметром `--local-step-ca`. Для этой проверки сертификаты и ключи читаются из
`secrets/`, не изменяются и не копируются в тестовую базу.

Операторский API восстановления реализован и проверен в тестах; для его
практического использования отдельно потребуется безопасный способ назначить
роль `SUPER_ADMIN`. Метод Identity `CheckSession` реализован; подключение
будущего вызывающего сервиса не требуется для локальной проверки регистрации
и входа.
Вход для восстановления `PENDING`, обычный вход для `ACTIVE` и ротация refresh
реализованы; logout остаётся отдельной задачей.
