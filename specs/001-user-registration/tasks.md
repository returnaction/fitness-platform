# Задачи: регистрация пользователя

> **Спецификация:** [spec.md](spec.md)  
> **План:** [plan.md](plan.md)  
> **Статус:** in progress

Задачи ниже задают порядок работы, но не резервируют номера будущих веток.
Для каждого следующего шага создаётся новая ветка с номером на единицу больше
предыдущего использованного номера.

## Уточнение до реализации

- [ ] [Security] Настроить и измерить Argon2id (`19456 KiB`, 2 итерации, 1 поток, соль 16 байтов, hash 32 байта); проверить обновление hash при усилении параметров.
- [x] [API] Реализовать ASCII email v1, пароль 1–128 символов/до 1024 UTF-8 байтов и локальный лимит регистрации 5 запросов с IP в минуту.
- [x] [Контракты] Зафиксировать OpenAPI регистрации и `.proto` `EnsureProfile` / `EnsureWallet`.
- [ ] [gRPC] Настроить mTLS с private CA / step-ca, URI SAN service identity, deadlines и коды ошибок.
- [ ] [Data] Сверить окончательный DDL Accounts и Coins с владельцами таблиц; Liquibase master changelog Identity и его начальная схема определяются в ветке `7-identity-registration-persistence`.

## Локальная платформа и каркас сервисов

- [ ] [Platform] Поднять Kafka через Docker Compose в KRaft-режиме без ZooKeeper; не создавать `UserRegistered` topic в v1 и документировать порты и безопасные переменные среды.
- [ ] [Platform] Настроить Caddy для внешнего HTTPS и private CA / mTLS для внутреннего gRPC; не публиковать gRPC-порты в интернет.
- [ ] [PostgreSQL] Создать в локально установленном PostgreSQL отдельные базы `fitness_identity`, `fitness_accounts`, `fitness_coins` и отдельные роли с минимальными правами.
- [ ] [Services] Создать Maven-модули Identity, Accounts и Coins, каждый с Actuator, конфигурацией окружения, Liquibase и изолированным подключением к своей базе.
- [x] [Contracts] Добавить версионируемые Protobuf-контракты и генерацию кода в Maven-сборке.

## Реализация

- [x] [Identity] Добавить Liquibase-миграции и доменную модель `PENDING`-регистрации с уникальным email и digest ключа.
- [x] [Accounts] Реализовать идемпотентный `EnsureProfile` с уникальным `user_id` и генерацией ника без перезаписи существующего профиля.
- [x] [Coins] Реализовать идемпотентный `EnsureWallet` с уникальным `user_id` и нулевым начальным балансом.
- [ ] [Identity] Реализовать worker claim/lease/retry/fencing и gRPC-вызовы без открытой транзакции во время сети.
- [ ] [Identity] Реализовать активацию после двух `READY`, создание сессии и REST `POST /api/v1/auth/register`.
- [x] [Identity] Реализовать защищённые операторские read/resume операции для технически заблокированных регистраций.

## Проверка и выпуск

- [ ] [Тесты] Добавить unit-, PostgreSQL-интеграционные, gRPC-контрактные и сквозные тесты из `plan.md`.
- [ ] [Документация] Обновить OpenAPI, `.proto`, связанные `system-design`-документы и `.env.example`.
- [ ] [CI] Добавить в CI проверки модулей, Liquibase-валидации и тестов по мере появления сервисов.
- [ ] [Spec] Проверить все критерии готовности из `spec.md`, зафиксировать результаты PR и сменить статус на `implemented` только после фактической проверки.

Текущий прогресс: проверен путь создания профиля и кошелька, активации и
повторного запроса регистрации с выдачей сессии. Для полного завершения ещё
нужны, в частности, создание безопасного процесса выдачи роли оператора и
подключение вызывающего сервиса к проверке отзыва сессии
`CheckSession` (серверный метод Identity реализован).
Refresh и logout также ещё не реализованы; статус спецификации остаётся
`in progress`.
