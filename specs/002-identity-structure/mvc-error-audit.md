# Проверка ошибок HTTP в Identity

Проверка выполнялась локально на тестовой конфигурации Identity со Spring Security.
Запросы не использовали пользовательскую базу. Код `405` также проверен отдельно
в изолированном тесте MVC без Security.

| Запрос или условие | Проверенный результат | Примечание |
| --- | --- | --- |
| Отсутствующее тело или некорректный JSON для register, login и refresh | `400 invalid_request` | Единый JSON ошибки и совпадающий `request_id` в теле и заголовке; тест с Security. |
| Нет `Idempotency-Key` | `400 invalid_request` | Единый JSON ошибки. |
| Неподдерживаемый `Content-Type` | `415 unsupported_media_type` | Исправлено с `500`; проверяются register, login и refresh. |
| Неподдерживаемый HTTP-метод доходит до MVC | `405 method_not_allowed` | Есть заголовок `Allow`; проверка без Security. |
| `GET /api/v1/auth/register` | `403` | Запрос отклоняет Spring Security до MVC. |
| Неизвестный защищённый путь | `403` | Действующее правило Security `denyAll`. |
| `Accept: application/xml` для register, login и refresh | `406` без тела | Проверены все три маршрута через MockMvc с Security; регистрация дополнительно проверена HTTP-запросом к тестовому Tomcat. |
| Пустой JSON для refresh | `422 validation_error` | Проверена валидация обязательного `refreshToken` и наличие `X-Request-Id`. |
| Неверный UUID в пути восстановления | `400` | Существующий PostgreSQL HTTP-интеграционный тест с авторизованным SUPER_ADMIN; в этом прогоне не запускался. |
| Сбой доступа к БД при входе | `503 identity_unavailable` | Через MockMvc и Security с имитированным исключением сервиса; внутреннее сообщение не попадает в ответ, `request_id` совпадает с заголовком. |
| Ошибка формирования JSON-ответа | `500 internal_error` | Изолированный MVC-тест с тестовым контроллером: ошибка до отправки ответа; чувствительные данные из исключения не попадают в тело. |

Таблица не утверждает, что проверены все стандартные ошибки Spring. В текущих
контроллерах нет обязательных query-параметров или multipart-запросов, поэтому
сценарии их обработки не проверялись. Тест сбоя БД использует имитацию, а не
реально отключённый PostgreSQL. Если ответ уже начал отправляться клиенту,
замена его на единый JSON не гарантируется и этим тестом не проверена.
