# Спецификации продукта

Эта папка хранит спецификации отдельных продуктовых возможностей, которые ещё
предстоит реализовать или которые уже реализованы. Спецификация отвечает на
вопрос **«что именно должна делать функция»**. Она не заменяет архитектурные
документы в [`system-design`](../system-design/README.md): там описаны общие
границы системы, сервисы и принятые решения.

## Структура

```text
specs/
  templates/                   # Неизменяемые заготовки документов
    spec.md
    plan.md
    tasks.md
  001-user-registration/       # Одна конкретная продуктовая возможность
    spec.md
    plan.md
    tasks.md
```

Каталог вида `001-short-feature-name` создаётся для одной самостоятельной
пользовательской возможности, а не для класса, таблицы или технической
задачи. Номер уникален, последователен и никогда не используется повторно.

## Рабочий процесс

Перед созданием первой спецификации прочитать [конституцию проекта](constitution.md):
она задаёт обязательные технические принципы. Затем:

1. Создать следующий пронумерованный каталог функции и скопировать в него
   документы из `templates/`.
2. Сначала заполнить `spec.md`: цель, границы, сценарии, правила и критерии
   готовности. Не начинать реализацию, пока поведение не согласовано.
3. Заполнить `plan.md`: затрагиваемые сервисы, данные, API/события, риски и
   способ проверки. Ссылаться на конкретные материалы `system-design`.
4. Разбить план в `tasks.md` на небольшие проверяемые шаги. Обычно один шаг
   выполняется в отдельной ветке и Pull Request.
5. После реализации обновить статус спецификации и отметить проверку
   критериев готовности. Существенное новое поведение — новая спецификация
   либо явно описанное изменение существующей.

## Статусы

- `draft` — черновик, требования ещё обсуждаются.
- `approved` — поведение согласовано, можно планировать реализацию.
- `in-progress` — работа по плану началась.
- `implemented` — критерии готовности выполнены и проверены.
- `superseded` — заменена другой спецификацией; указывается ссылка на неё.

## Границы документов

| Документ | Главный вопрос |
| --- | --- |
| `system-design/` | Как в целом устроена система и какие решения приняты? |
| `specs/<номер>-<функция>/spec.md` | Какое пользовательское поведение и правила должны быть? |
| `plan.md` | Как безопасно реализовать это поведение в данной архитектуре? |
| `tasks.md` | Какие небольшие шаги нужно выполнить и проверить? |
| `contracts/` | Какой точный машинно-читаемый API, gRPC или формат события? |
