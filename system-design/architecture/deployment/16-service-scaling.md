# Масштабирование сервисов: учебная модель

У будущего сервиса может работать несколько равноправных копий. Gateway
направляет запросы к доступным копиям; соседние запросы одного пользователя
могут попасть в разные экземпляры.

Важные состояния, например участие и результат обработки, надёжно хранятся
в данных соответствующего сервиса, а не только в памяти одной копии. Само
использование базы не гарантирует корректности: конкурентные операции требуют
спроектированных транзакций и ограничений. Например, через разные копии
Challenge нельзя подтвердить двум игрокам одно последнее место.

Для обработки разных видео возможно несколько worker. Владение и завершение
одной задачи защищаются механизмом задания и проверки актуальной аренды в
PostgreSQL; RabbitMQ доставляет уведомления. Повторное завершение недопустимо.

Количество экземпляров не выбрано: его определяют по нагрузке и измерениям.
Способ балансировки, состояние здоровья, развёртывание и масштабирование базы
будут разобраны отдельно. Текущий код и инфраструктура этим документом не
изменяются.
