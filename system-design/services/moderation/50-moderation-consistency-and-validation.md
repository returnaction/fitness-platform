## Сверка API и данных

| Действие | Локальная транзакция Moderation | Защита от повтора / гонки |
| --- | --- | --- |
| Принять допуск | Inbox, карточка или отложенное ожидание и аудит. | `event_id` + бизнес-ключ допуска; payload-конфликт в карантин. |
| Назначить / вернуть дело | Версия дела, assignment, результат ключа и аудит. | Блокировка дела и частичный UNIQUE активного assignment. |
| Решить видео | Решение, состояние дела, результат ключа, audit и outbox. | UNIQUE решения по case, версия, авторизация; Challenge отдельно проверяет допуск. |
| Принять апелляцию | Inbox и карточка по `appeal_id`; подача и срок уже зафиксированы Challenge. | Повтор без второго дела, недостающая зависимость ждёт. |
| Решить апелляцию | Решение, статус, ключ, audit и outbox. | Одно решение; модератор не является автором первоначального. |
| Техническое дело | Inbox, дело по trigger и аудит; решение — отдельная версия с outbox. | `INCONCLUSIVE` оставляет дело открытым; противоречивый trigger не переписывает его. |
| Отозвать допуск | Сохранить версию или tombstone, закрыть карточку и назначение в одной транзакции. | Старое событие допуска не открывает карточку после tombstone. |

**Результат сверки:** проекты guard и durable-ожидания добавлены в
[Moderation](45-moderation-data-model.md), стабильный ID и версия допуска и

повтора — в [Video Proof](../video-proof/40-video-proof-service.md). Осталось формализовать

## Хранение — согласованные сроки учебного v1

- Завершённый HTTP-результат идемпотентности — не менее **90 суток** после
  завершения; незавершённый не удаляется автоматически. После удаления старого
  ключа уникальные бизнес-ограничения продолжают запрещать второе решение.
- Решения и аудит — минимум **один год** после окончательного закрытия дела;
  открытые дела и связанные доказательства по этому правилу не удаляются.
- Проект Kafka — 30 суток, inbox/APPLIED не менее 90 суток с дополнительными
  условиями безопасного replay, незавершённые ожидания и guards без короткого
  TTL: [политика событий](../../architecture/recovery/52-event-retention-and-validation.md).
  Автоматическая очистка guard и inbox/APPLIED в v1 выключена; граница для
  будущего удаления и архивирования остаётся открытой.
- Данные о видео удаляются по отдельному правилу 30 дней после окончательного
  завершения challenge; удаление файлов не удаляет историю решений или ledger.

90 дней и год согласованы пользователем для учебной модели; это не проверенные
юридические требования и не гарантия реализации. До публичного запуска нужны
применимые требования и процедура удаления.
Сверка event ID с другим payload требует сохранять digest в срок дедупликации.

## Набор проверок перед готовностью реализации

1. **PostgreSQL:** два назначения, release против decision, два разных решения,
   один ключ с одинаковым и другим payload, rollback между решением / outbox /
   audit, завершение срока ключа без повторной бизнес-операции.
2. **Авторизация:** своя запись и собственная апелляция, чужое назначение,
   отзыв роли, подмена пользователя в заголовках, недоступная Identity или
   Challenge, временный URL и новая проверка после его истечения.
3. **Kafka + две БД:** повтор event ID, новый event ID с тем же бизнес-ключом,
   падение после commit до offset, недоступная Moderation, отзыв перед допуском,
   задержка события, неверная версия и раннее решение относительно апелляции.
4. **Бизнес-сценарий:** четыре вердикта, право апелляции только по технике,
   своевременная подача при задержке Kafka, другой модератор, решение по
   апелляции, удержание видео следующего дня и применение результата Challenge.
5. **Хранилище и медиа:** верная версия playback, поворот, звук, повторная
   выдача URL, потеря доступа во время просмотра, невыдача ссылки на чужое или
   неподходящее видео; проверка срока приёма на фактическом S3-провайдере.
6. **Технический разбор:** `INCONCLUSIVE` не означает вину и не завершает дело;
   retry после исправления, stale worker и повтор событий не создают две
   обработки или два исхода.

Эти проверки ещё не запускались. Требования публичного запуска, таблицы и
контракты, перечисленные как пробелы, пока не закрыты.
