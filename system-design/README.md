# System Design — документация проекта

Мы проектируем будущую систему на **Java / Spring**. Документы в этой папке — проект для разработки и обучения, а не описание уже реализованных микросервисов. Действующее приложение на Python / FastAPI используется как пример.

## С чего начать

1. [Требования](requirements/README.md) — что должна делать система и какие допущения мы используем.
2. [DDD и словарь](domain/README.md) — общие термины, предметная область и границы контекстов.
3. [Общая архитектура](overview/README.md) — схема системы, текущий статус и карта работ.
4. [Взаимодействия сервисов](interactions/README.md) — кто кому отправляет запросы и события.
5. [Сервисы](services/README.md) — таблицы, API, правила и сценарии каждого сервиса.
6. [Инфраструктура](architecture/README.md) — Kafka, RabbitMQ, безопасность, развёртывание и восстановление.
7. [Архитектурные решения](decisions/0001-new-project-and-domain-boundaries.md) — принятые направления и ADR; [взаимодействие сервисов](decisions/0002-service-communication.md).

Диаграммы `.drawio` открываются в draw.io / diagrams.net. Номер в имени файла сохраняет историю создания и **не означает порядок чтения**. В каждой папке есть собственный README с перечнем материалов.

Документы остаются проектными: наличие схемы или API не означает, что код написан или протестирован. Таблица данных определяется один раз в документе её владельца; остальные документы на неё ссылаются. Правила работы с документацией — [AGENTS.md](AGENTS.md).
