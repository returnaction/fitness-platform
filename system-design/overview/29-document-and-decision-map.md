# Инвентаризация документов и архитектурных решений

Учебная модель системы на Java / Spring. Она не меняет действующий Python-монолит
и не заменяет ADR текущего проекта в `docs/decisions/`. Статусы ниже отражают
обсуждение, а не реализованную функциональность или готовность к production.

## Карта паттернов

| Механизм | Где и зачем | Статус и ограничения |
| --- | --- | --- |
| Retry с задержкой | Временная недоступность Coins, БД, сети или задачи видео. | Выбран принцип; интервалы и пределы подбираются отдельно. Повтор только при безопасной идемпотентности; таймаут не означает отказ. |
| Circuit breaker | Кандидат для синхронных вызовов Challenge → Coins / Identity. | Предложение, не согласованный обязательный стандарт. Не заменяет таймауты и восстановление незавершённой операции. |
| Идемпотентность | Вступление, принятие видео, решения, начисления. | Согласовано: event ID и отдельный бизнес-ключ; конфликтные повторы не выполнять повторно. |
| Transactional outbox / inbox | Сохранение факта и исходящего события; безопасное применение повторов получателем. | Согласовано как направление; локальная транзакция не делает общей транзакцией две БД и Kafka. |
| Saga / компенсация | Резерв ставки перед подтверждением места; освобождение резерва при окончательной неудаче. | Сценарий согласован; устойчивое состояние и гонки ещё спроектировать. |
| Lease и fencing token | Несколько обработчиков видео при сбое и перезапуске. | Выбран принцип; старый исполнитель не должен подтверждать устаревший результат. |
| DLQ / карантин | Битое сообщение или неподдерживаемая схема. | Некорректные данные не повторяются бесконечно; повтор после разбора контролируется. Временный отказ БД обрабатывается иначе. |
| CQRS | Возможное отдельное представление для поиска challenge. | Не принято как обязательный подход; отдельный сервис или БД чтения пока не требуются. Обычные команды и запросы не доказывают наличие CQRS. |
| Event Sourcing | Восстановление состояния из последовательности доменных событий. | Не выбран; неизменяемый ledger Coins сам по себе не означает Event Sourcing всей системы. |

## Найденные расхождения и ограничения

- [Требования](../requirements/02-requirements.md) содержат помеченные исторические блоки о
  старом сроке апелляции и начисления; рабочие заметки содержат и другие старые
  правила. При подготовке формальной спецификации стоит удалить противоречия
  из основного текста, сохранив историю отдельно.
- Удаление видео: в требованиях и хранении согласованы 30 дней после финала;
  в истории встречается прежний дополнительный отсчёт после апелляции.
- Роли модерации и список состояний — проектные решения; действующий монолит
  использует другую модель, включая общий `REJECT`.
- Общая модель репликации на одном физическом сервере не подтверждает устойчивость
  к отказу сервера; RTO Coins до пяти минут не вытекает из ожидания восстановления A.
- Расчёт одного видео на участника — упрощение; несколько заданий увеличивают
  количество видео и нагрузку. Модератор с неограниченной пропускной способностью
  — учебное допущение, не производственный расчёт.
- Диаграммы проверялись как XML и на ссылки рёбер; визуальная проверка в draw.io
  в рамках этой инвентаризации не выполнялась.

## Следующий рабочий шаг

Уточнить для ближайшего выбранного сценария сущности, инварианты, контракт и
проверки. Перед фактическим созданием Java-приложения отдельно определить его
размещение и план совместимости; реализация сейчас не начинается.
