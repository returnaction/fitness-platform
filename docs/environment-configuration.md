# Настройки окружения сервисов

Для каждого сервиса `.env.example` — шаблон без настоящих паролей. При первой
локальной настройке скопируйте его в `.env` рядом с шаблоном и заполните свои
значения. Локальный профиль Spring читает `.env`, но не `.env.example`. Изменения
шаблона не обновляют уже созданный `.env` автоматически.

Файлы `.env` и закрытые ключи не добавляются в Git. В тестах Identity, Accounts
и Coins используются отдельные `src/test/resources/test-environment.properties`;
интеграционные тесты при необходимости заменяют параметры базы значениями
временной PostgreSQL и используют временные ключи. Сквозной тест берёт те же
тестовые настройки и не читает личные `.env` и шаблоны.

## Как это будет работать на сервере

Развёртывание ещё не настроено. При его подготовке для каждого сервиса нужно
отдельно создать серверные значения: адрес и учётные данные его базы, порт,
ключи и другие необходимые настройки. Локальные пароли туда автоматически не
копируются. Серверные файлы с секретами хранятся вне Git и Docker-образа.

Один из вариантов — Docker Compose: серверный файл, например
`/etc/fitness/identity.env`, указывается в `env_file` сервиса. Compose передаст
его значения как переменные окружения контейнера, а Spring подставит их в
`application.yaml`. Для сервера явно выбирается профиль, отличный от `local`,
например `SPRING_PROFILES_ACTIVE=server`; соответствующие обязательные переменные
нужно передать при запуске. Ключи и сертификаты при необходимости также должны
быть доступны приложению через отдельно настроенные защищённые файлы.

Это описание варианта, а не действующая конфигурация сервера. Пути, права,
способ передачи секретов и обновления файлов нужно будет настроить и проверить
при отдельной задаче развёртывания.
