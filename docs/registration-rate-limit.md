# Ограничение запросов регистрации

Для одного экземпляра Identity `POST /api/v1/auth/register` ограничен локальным
Bucket4j token bucket: пять запросов за период 60 секунд. Первые пять запросов
занимают токены, после чего полный набор восстанавливается в конце периода.
Учитываются также запросы с некорректным JSON или отсутствующим заголовком.
При превышении сервис отвечает `429 rate_limited` и `Retry-After` в секундах.

Значения задаются в `.env.example` и могут быть переопределены в `.env` или
окружении сервера: `IDENTITY_REGISTRATION_RATE_CAPACITY`,
`IDENTITY_REGISTRATION_RATE_PERIOD_SECONDS`,
`IDENTITY_REGISTRATION_RATE_CACHE_SIZE` и
`IDENTITY_REGISTRATION_RATE_CACHE_EXPIRY_SECONDS`. Состояние хранится в
Caffeine в памяти процесса, при перезапуске оно исчезает. Размер кэша ограничен:
при его заполнении вытесненный адрес может получить новый bucket до окончания
периода. Для нескольких экземпляров или защиты от массового перебора адресов
нужен отдельный согласованный общий backend; локальный кэш не даёт такой гарантии.

Для `POST /api/v1/auth/login` действует отдельный bucket на тот же IP: начальное
значение `IDENTITY_LOGIN_RATE_CAPACITY=10` запросов за тот же период. Вход и
регистрация не расходуют токены друг друга.

Для `POST /api/v1/auth/refresh` используется ещё один независимый bucket:
начальное значение `IDENTITY_REFRESH_RATE_CAPACITY=30` запросов за период.

По умолчанию `IDENTITY_REGISTRATION_TRUSTED_PROXY_IP` пуст, и клиент определяется
по непосредственному IP-соединению. Для Caddy можно явно указать его точный IP;
только при совпадении адреса соединения берётся последний адрес из
`X-Forwarded-For`. Некорректный заголовок не доверяется. Конфигурация допустима
только если к Identity с этого IP не могут напрямую подключаться другие клиенты,
а Caddy очищает недоверенные входные forwarded-заголовки. Настройки прокси и
сетевую изоляцию нужно проверить при развёртывании. Без доверенного прокси все
запросы через него будут учитываться как один IP.
